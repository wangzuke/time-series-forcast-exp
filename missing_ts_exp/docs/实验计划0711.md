# 实验计划 0711：缺失可靠性感知的分组 Query 融合（诊断 + 门控融合）

> 承接：《0709实验报告.md》关于自动分组的结论、《0710实验报告.md》关于观测相关性与双路融合的正负结果，以及对 MissTSM、GinAR/IBN、DUET、CRAFT 等相关工作的调研。
> 计划日期：2026-07-11
> 核心目标：将前两轮“哪一种分组方式更好”的经验性比较，收束为一个更明确的课题问题：**在缺失多变量时间序列预测中，通道依赖先验的可靠性会随数据集、缺失类型、缺失率和具体观测状态变化；模型需要显式判断当前应依赖预定义先验、观测相关性，还是自适应路由。**

---

## 一、课题背景与问题重述

### 1.1 目前已经确认的事实

0709 与 0710 两轮实验已经给出了一组比较清晰的事实，而不是单纯的模型排行榜。

1. **单 query 聚合存在信息瓶颈，分组 query 是合理扩展方向。**  
   MissTSM 的 `full` 变体用单个可学习 query 在每个时间步聚合所有变量信息。R4/0709 的 `grouped_q4` 结果说明，将通道拆成多个 query group 后，在 Weather 等存在物理变量组结构的数据集上可以带来稳定收益。这与 MissTSM 原文讨论中提到的 grouped / hierarchical aggregation 方向一致。

2. **静态相关性先验并不总可靠。**  
   0709 的 `grouped_q4_corr` 证明，训练前用完整训练序列计算一次 Pearson 相关性，再据此重排通道，并不能稳定改善分组质量。Traffic 随机点缺失下进一步退化，Weather `continuous_segment` 中高缺失率下也出现退化。这说明“完整数据上的通道相关性”并不等价于“缺失输入条件下模型实际可利用的依赖结构”。

3. **观测相关性可以局部修复静态先验失真。**  
   0710 的 `grouped_q4_corrobs` 在 Weather `continuous_segment` 50%/70% 和 Traffic `random_point` 50% 上明显优于 `grouped_q4_corr`。这说明缺失模式确实会改变通道依赖先验的有效性，尤其在高缺失率或结构化缺失下更明显。但 `corrobs` 在 Traffic `continuous_segment` 上没有收益，因此它不是通用解。

4. **自适应软路由在 Traffic 上有效，但不是所有场景都好。**  
   0709 的 `grouped_q4_soft` 基本修复了 Traffic 上序号切分的不稳定问题，并且跨种子稳定性接近 `full`。但它在 Weather `continuous_segment` 下也会退化，且训练时间显著增加。这说明纯自适应路线能绕开坏先验，但也可能缺少中维物理变量场景中有价值的先验约束。

5. **无门控的双路融合只在部分场景协同，在 Traffic 上会被坏先验拖累。**  
   0710 的 `grouped_q4_fuse` 在 Weather 上出现真实协同，尤其 `continuous_segment` 50% 同时超过 `corr` 和 `soft`。但 Traffic 上 6 个条件全部劣于 `soft`，说明“预定义路径 + 自适应路径直接相加”并不能保证模型自动忽略失效先验。当前融合结构缺少一个显式的可靠性判断机制。

### 1.2 课题主线的收束

基于上述事实，本研究不再把后续工作定义为继续枚举更多分组方式，而是收束到如下问题：

> **在缺失多变量时间序列预测中，如何让 MissTSM-style grouped query aggregation 根据当前缺失状态和先验可靠性，动态选择预定义先验路径与自适应路由路径的贡献？**

这个问题对应一个更有创新产出潜力的小方向：

> **Reliability-Gated Grouped Query Aggregation（可靠性感知的分组 Query 聚合）**

其核心思想是保留 0710 中已经验证有正面证据的两路结构：

- 路径 A：预定义相关性分组路径，对应 `grouped_q4_corr` 或 `grouped_q4_corrobs`。
- 路径 B：自适应软路由路径，对应 `grouped_q4_soft`。

但不再简单相加：

```python
attn_out = attn_out_A + attn_out_B
```

而是引入可靠性门控：

```python
attn_out = gate * attn_out_A + (1 - gate) * attn_out_B
```

其中 `gate` 应当能根据当前窗口的缺失状态、组内观测率、先验分组稳定性或路由不确定性，判断当前更应相信哪一路。

### 1.3 与已有工作的关系

这一方向与已有工作的关系如下：

| 工作方向 | 代表工作 | 与本研究的关系 |
|---|---|---|
| MissTSM 单 query 缺失感知聚合 | MissTSM | 本研究沿着其 grouped / hierarchical aggregation 讨论方向展开，但重点放在缺失条件下的通道分组可靠性 |
| 预定义图 + 自适应图融合 | GinAR、IBN | 0710 已借鉴其双路融合思想；0711 进一步补上“坏先验需要被显式抑制”的可靠性门控 |
| 通道聚类 / 通道重排 | DUET、CRAFT | 这些工作说明通道分组和重排本身有价值；本研究关注缺失模式下先验分组何时可靠、何时失效 |
| 高维通道自适应路由 | U-Cast、相关 latent query 工作 | 与本研究共享“用可学习 query / latent structure 捕获通道结构”的思想，但本研究强调 missing-aware aggregation |

因此，0711 的目标不是简单追求某个 benchmark 条件下的更低 MSE，而是验证一个可解释、可写入论文主线的机制假设：**通道依赖先验需要被可靠性感知地使用，而不是静态使用或盲目融合。**

## 二、本轮核心假设

### 2.1 假设 F：0710 中 Traffic 融合失败的直接原因是坏先验路径未被压低

0710 的 `grouped_q4_fuse` 在 Traffic 上全部劣于 `grouped_q4_soft`。计划中的理论预期是：如果预定义路径无用，`group_proj_A` 可以在训练中学到接近零的贡献。但实测结果没有体现这种自动抑制。

本轮首先需要通过 checkpoint 诊断回答：

1. Traffic 上 `group_proj_A` 与 `group_proj_B` 的权重范数是否接近？
2. `attn_out_A` 与 `attn_out_B` 的输出范数是否接近？
3. 两路输出的 cosine similarity 是否较低，甚至互相冲突？
4. soft route 是否接近均匀分布，还是形成了明确分组？

若 Traffic 上预定义路径贡献并未被压低，而结果又被融合拖累，则说明可靠性门控是必要的，而不是可有可无的工程增强。

### 2.2 假设 G：显式门控可以保留 Weather 的融合协同，同时避免 Traffic 的坏先验拖累

在 Weather 上，预定义相关性路径有物理变量组结构支撑；在 Traffic 上，静态相关性或相关性重排经常不可靠。一个有效的门控机制应当体现如下行为：

- Weather `continuous_segment` 中高缺失率：保留或增强先验路径贡献，不破坏 0710 `fuse` 的协同收益。
- Traffic `random_point` / `continuous_segment`：压低预定义路径贡献，使结果接近或超过 `grouped_q4_soft`。
- Electricity：由于各分组方式长期无区分度，门控不应引入明显退化。

### 2.3 假设 H：mask-aware gate 比全局可学习 gate 更符合缺失预测问题

如果只学习一个全局 scalar gate，模型只能学习“这个数据集整体更信先验还是更信自适应”。但 0710 的结果说明，可靠性不仅随数据集变化，也随缺失类型和缺失率变化。例如：

- Weather `continuous_segment` 50%/70%：`corrobs` 与 `fuse` 都有正面证据。
- Weather `random_point` 50%：`fuse` 反而劣于 `corr`。
- Traffic `random_point` 50%：`corrobs` 局部有效，但 `fuse` 仍输给 `soft`。

因此，本轮需要比较三种门控层级：

1. **全局 scalar gate**：最小改动，验证“可学习抑制某一路”是否有用。
2. **group-level gate**：每个 query group 一套门控，允许不同组使用不同路径。
3. **mask-aware gate**：根据当前窗口和当前组的观测率动态生成 gate，直接体现缺失感知。

- `grouped_q4_soft` 是否学到了有意义的路由；
- `grouped_q4_fuse` 是否真的压低了失效预定义路径；
- Weather 上的正向协同与 Traffic 上的负向拖累在内部表示上有什么差异。

Phase 0 不引入新模型，只补充保存与分析工具。

不需要全量重跑 72 条。优先选择能代表正负机制的条件：

| 数据集 | 缺失类型 | 缺失率 | 变体 | 目的 |
|---|---|---:|---|---|
| Weather | continuous_segment | 0.5, 0.7 | `grouped_q4_soft`, `grouped_q4_fuse` | 正向协同条件，观察先验路径是否确实贡献较大 |
| Weather | random_point | 0.5 | `grouped_q4_fuse` | 0710 中融合负例，观察 gate 需求 |
| Traffic | random_point | 0.3, 0.5 | `grouped_q4_soft`, `grouped_q4_fuse` | Traffic 上 soft 强、fuse 被拖累的关键条件 |
| Traffic | continuous_segment | 0.7 | `grouped_q4_soft`, `grouped_q4_fuse` | Traffic 上 fuse 最明显退化条件 |
| Electricity | random_point | 0.5 | `grouped_q4_fuse` | 无区分度负例，检查两路是否都弱贡献 |

种子先使用 2024、2025，与已有实验保持一致。若诊断结果高度依赖种子，再补 2026。

### 3.4 判定标准

Phase 0 希望回答三件事：

1. Traffic 上 `fuse` 失败时，预定义路径是否仍有较大输出或权重范数。若是，则支持“坏先验没有被自动压低”的解释。
2. Weather 上 `fuse` 成功时，两路输出是否互补，而不是其中一路完全支配。若两路 cosine similarity 较低但融合效果好，说明双路结构确有互补性。
3. `grouped_q4_soft` 的 route entropy 是否显著低于 `log(4)`。若接近均匀，则 Traffic 上的收益可能更多来自多 query / 多 MHA 容量，而不是真正分组；这会影响后续论文表述。

## 四、Phase 1：可靠性门控融合主实验

### 4.1 新变体定义

本轮主实验在 `grouped_q4_fuse` 的基础上增加三种门控变体。

#### 4.1.1 `grouped_q4_fuse_sgate`：全局 scalar gate

最小门控版本。模型学习一个标量参数 `alpha`：

```python
gate = torch.sigmoid(alpha)  # scalar
attn_out = gate * attn_out_A + (1 - gate) * attn_out_B
```

其中：

- `attn_out_A` 是预定义相关性硬分组路径输出；
- `attn_out_B` 是自适应软路由路径输出；
- `alpha` 初始化为 0，使初始 gate=0.5，与 0710 的无门控相加相比更接近“平均融合”，避免一开始偏向某一路。

该变体用于验证：即使不引入 mask 信息，仅让模型显式学习两路权重，是否已经能缓解 Traffic 上坏先验拖累。

#### 4.1.2 `grouped_q4_fuse_ggate`：group-level gate

每个 query group 学一个 gate：

```python
gate_g = torch.sigmoid(alpha_g)  # (G,)
mixed_g = gate_g * out_A_g + (1 - gate_g) * out_B_g
attn_out = group_proj_mix(concat(mixed_1, ..., mixed_G))
```

与 scalar gate 相比，group-level gate 允许模型表达“某些组的先验可靠，某些组更应依赖自适应路由”。这对 Weather 这类变量组结构清晰的数据集尤其重要，因为温度、湿度、风速、辐射等组的先验可靠性可能不同。

#### 4.1.3 `grouped_q4_fuse_mgate`：mask-aware group gate

本轮最核心变体。每个 `(B*L, group)` 根据当前输入窗口的观测情况动态生成 gate。

建议的第一版 gate 特征保持简单：

```python
global_obs = 1 - pad_mask.float().mean(dim=1)        # (B*L, 1)
group_obs_g = 1 - pad_g.float().mean(dim=1)          # (B*L, 1)
all_missing_g = pad_g.all(dim=1).float().unsqueeze(1)
gate_input_g = concat([global_obs, group_obs_g, all_missing_g], dim=-1)
gate_g = sigmoid(MLP(gate_input_g))                  # (B*L, 1)
mixed_g = gate_g * out_A_g + (1 - gate_g) * out_B_g
```

第一版不加入复杂特征，避免把机制做得过重。若这一版有效，后续再考虑加入：

- group 内缺失连续片段长度统计；
- route entropy；
- prior group 内平均相关性；
- `corrobs` 在不同 mask seed 下的 group order 稳定性。

`mgate` 的预期行为是：

- 当某个硬分组内观测率很高时，可以更多使用先验路径；
- 当某个硬分组大量缺失甚至全缺失时，应更多使用自适应路径；
- 在 Traffic 这类先验不可靠的数据集上，即使观测率不低，训练也应通过 gate MLP 学会压低先验路径。

### 4.4 判定标准

Phase 1 的核心判据不是单点最优，而是是否符合可靠性门控的预期行为。

1. **Traffic 不拖累判据**  
   在 Traffic 的 4 个条件中，门控变体相对 `grouped_q4_fuse` 至少 3 个条件改善，且不应显著劣于 `grouped_q4_soft`。允许 <1% 波动；若仍全面劣于 `soft`，说明当前 gate 未能解决坏先验问题。

2. **Weather 保收益判据**  
   在 Weather `continuous_segment` 0.5/0.7 中，门控变体不应破坏 0710 `fuse` 的协同收益。若 `mgate` 在这两个条件下接近或优于 `fuse`，同时 Traffic 上接近 `soft`，则说明门控实现了“保留好先验、抑制坏先验”。

3. **mask-aware 优于静态 gate 判据**  
   若 `mgate` 在不同缺失率下表现更稳定，且 gate 值随 group observed ratio 或 missing rate 呈现可解释变化，则支持假设 H。若 `sgate` 与 `mgate` 表现接近，则说明数据集级路径选择可能已足够，后续方法可以保持更简单。

4. **Electricity 不退化判据**  
   Electricity 两个条件下，门控变体相对 `soft` / `fuse` 的差异应控制在 2% 内。若出现明显退化，说明门控增加了不必要自由度，需要考虑更强正则或更简单 gate。

## 五、Phase 2：先验来源与门控的叠加验证

### 5.1 触发条件

只有当 Phase 1 中 `grouped_q4_fuse_mgate` 或 `grouped_q4_fuse_ggate` 满足以下条件时，才进入 Phase 2：

- Traffic 上相对 `fuse` 明显改善，且接近 `soft`；
- Weather `continuous_segment` 0.5/0.7 不破坏 `fuse` 的协同收益；
- gate 诊断显示先验路径贡献确实随条件变化，而不是恒定偏向某一路。

### 5.2 新变体

Phase 2 验证“观测相关性先验”是否能与门控融合互补。

| 变体 | 含义 |
|---|---|
| `grouped_q4_fuseobs_mgate` | 与 `grouped_q4_fuse_mgate` 相同，但预定义路径使用 `grouped_q4_corrobs` 的观测相关性 `group_order` |
| `grouped_q4_fuseobs_ggate`（可选） | 若 Phase 1 中 `ggate` 优于 `mgate`，则同步验证 group-level gate + 观测相关性 |

### 5.3 实验条件

不全量跑 36 条，只验证 0710 中 `corrobs` 有正面证据或明确边界价值的条件：

| 数据集 | 缺失类型 | 缺失率 | 目的 |
|---|---|---:|---|
| Weather | continuous_segment | 0.5, 0.7 | `corrobs` 明显改善，验证观测先验 + gate 是否进一步优于静态先验 + gate |
| Weather | random_point | 0.5 | 0710 中 `fuse` 负例，检验观测先验是否会误伤 |
| Traffic | random_point | 0.5 | `corrobs` 最大单点改善，验证能否与 gate 叠加 |
| Traffic | continuous_segment | 0.7 | `corrobs` 无收益且 `fuse` 退化最大，作为负面对照 |

实验量：

```text
5 个条件 × 1-2 个新变体 × 2 个种子 = 10-20 条训练
```

### 5.4 判定标准

- Weather `continuous_segment` 0.5/0.7 中，`fuseobs_mgate` 应优于或接近 `fuse_mgate`，且不劣于 0710 的 `fuse`。
- Traffic `random_point` 0.5 中，`fuseobs_mgate` 若优于 `fuse_mgate`，说明观测相关性可作为局部更可靠先验。
- Traffic `continuous_segment` 0.7 中，若 `fuseobs_mgate` 仍不能接近 `soft`，说明该条件下应完全依赖自适应路径，而不是继续改先验来源。

## 七、需要记录的诊断指标

除 MSE / MAE / 训练时间 / 参数量外，本轮必须记录以下诊断指标，否则无法支撑“可靠性感知”的课题叙事。

| 指标 | 适用变体 | 目的 |
|---|---|---|
| route entropy | `soft` / `fuse*` / `gate*` | 判断自适应路由是否退化为均匀分配 |
| top-1 group 分布 | `soft` / `fuse*` / `gate*` | 判断是否出现组塌缩或严重负载不均 |
| effective group count | `soft` / `fuse*` / `gate*` | 衡量每个通道实际使用多少组 |
| `proj_A/proj_B` 权重范数 | `fuse` / `gate*` | 判断模型是否压低失效路径 |
| `out_A/out_B` 输出范数 | `fuse` / `gate*` | 判断两路实际贡献大小 |
| 两路 cosine similarity | `fuse` / `gate*` | 判断两路互补还是冲突 |
| gate 均值与方差 | `sgate` / `ggate` / `mgate` | 判断门控是否真的变化 |
| gate vs observed ratio 相关性 | `mgate` | 判断 mask-aware gate 是否利用缺失状态 |
| group 内平均相关性 | `corr` / `corrobs` / `fuse*` | 判断先验分组质量 |

报告中至少需要给出：

1. Weather 正例条件下的 gate 分布；
2. Traffic 负例条件下的 gate 分布；
3. gate 与 MSE 改善之间的对应关系。

如果 `mgate` 表现好但 gate 无法解释，则方法虽然有效，但论文叙事会弱很多；如果 gate 变化与缺失状态高度相关，则可以形成较强的可解释性贡献。

## 八、代码实现注意事项

### 8.1 不改变已有变体行为

`full`、`grouped_q4`、`grouped_q4_corr`、`grouped_q4_corrobs`、`grouped_q4_soft`、`grouped_q4_fuse` 的行为必须保持不变，以便继续复用 R4/0709/0710 的历史结果。

新增门控变体应通过新的 variant 名称触发，不应修改现有 `grouped_q4_fuse` 的 forward 逻辑。

### 8.2 gate 初始化

初始 gate 建议为 0.5：

```python
alpha = 0
gate = sigmoid(alpha) = 0.5
```

这样不会在训练初期人为偏向先验路径或自适应路径。若后续发现 Traffic 上仍被先验拖累，可增加一个消融版本，将 gate 初始化为偏向自适应路径，例如 `alpha=-1.0`，但不作为 Phase 1 主实验默认设置。

### 8.3 mask-aware gate 特征先保持简单

第一版 `mgate` 只使用：

- global observed ratio；
- group observed ratio；
- all-missing group indicator。

不在第一版加入复杂统计，避免出现“模型有效但不知道是哪一个特征起作用”的问题。若第一版有效，再逐步加入连续缺失长度、route entropy、prior stability 等特征。

### 8.4 训练成本记录

`fuse_mgate` 预期计算量接近 `fuse`，因为两路注意力计算不变，只多一个很小的 gate MLP。但仍必须记录：

- 平均单 epoch 时间；
- peak memory；
- 参数量；
- 相对 `soft` 和 `fuse` 的增量。

### 8.5 不自动启动训练

本计划只定义实验设计和实现细节。代码实现完成后，应先做 smoke test 和参数量检查，再确认是否启动 Phase 0/1 的训练命令。

## 十、预期结论形式

0711 报告应围绕以下问题组织，而不是只按变体逐个报数。

1. **Traffic 上融合失败是否确实来自坏先验未被压低？**  
   需要用 Phase 0 的 `proj_A/proj_B`、`out_A/out_B`、cosine similarity 等诊断回答。

2. **显式门控是否能同时保住 Weather 的协同收益并避免 Traffic 的坏先验拖累？**  
   这是 Phase 1 的核心结果。如果成立，说明可靠性感知融合是比 0710 简单相加更合理的机制。

3. **mask-aware gate 是否比全局 gate 更符合缺失预测问题？**  
   如果 `mgate` 相对 `sgate` / `ggate` 更稳，并且 gate 与 observed ratio 有可解释关系，则支持“缺失状态决定先验可靠性”的课题主张。

4. **观测相关性先验是否值得与 gate 叠加？**  
   Phase 2 只在局部条件验证。如果收益集中在 Weather 高缺失连续片段和 Traffic random 50%，报告中应如实表述为局部增强，而不是通用改进。

5. **最终可推进的论文方向是什么？**  
   若门控有效，后续主线应从“MissTSM 分组 query 消融”升级为“缺失可靠性感知的 grouped query aggregation”。若门控无效，则应回到更保守的结论：`soft` 是 Traffic 推荐方案，`fuse` 是 Weather 推荐方案，方法选择需要按数据集/缺失类型分支，而不是统一模型。

## 十一、成功与失败的解释边界

### 11.1 成功标准

本轮最理想的结果是：

- `grouped_q4_fuse_mgate` 在 Weather `continuous_segment` 0.5/0.7 接近或超过 0710 `fuse`；
- 在 Traffic 4 个条件中接近或超过 `grouped_q4_soft`，至少明显优于 0710 `fuse`；
- gate 诊断显示 Weather 更偏向先验路径，Traffic 更偏向自适应路径，且这种偏向随缺失率或组内观测率变化。

这将形成一个可以写入论文的机制闭环：

```text
缺失模式改变通道依赖先验可靠性
→ 静态先验和纯自适应各有适用场景
→ 无门控融合会被坏先验拖累
→ 可靠性感知 gate 可以动态选择依赖来源
```

### 11.2 部分成功标准

若 `sgate` 或 `ggate` 已经足够有效，而 `mgate` 没有额外收益，则说明当前数据集上“数据集级/组级可靠性”比“样本级缺失状态”更主要。此时方法可以保持简单，论文贡献转向“learnable reliability gating”，而不是强调 mask-aware dynamic gating。

### 11.3 失败标准

若所有 gate 变体都无法改善 Traffic 上 `fuse` 的退化，且仍劣于 `soft`，则说明当前双路融合结构不适合 Traffic。后续应停止在 Traffic 上融合先验路径，把 Traffic 作为“自适应路由优先”的边界条件。此时仍可以保留 Weather 上 `fuse` 的正面结果，但不应声称存在统一有效的融合机制。

若 gate 有效但诊断指标不可解释，则需要谨慎处理论文表述：可以报告性能改进，但不能把 gate 强行解释为可靠性判断机制。
