## 一、两轮实验核心发现回顾

### 1.1 稳定结论（两轮一致）

| 编号 | 结论 | 证据强度 |
|---|---|---|
| C1 | 线性插值 + iTransformer 全局最优（MSE 0.2834） | 强：跨 3 数据集、4 缺失类型、5 缺失率一致 |
| C2 | 预测模型选择 > 缺失处理策略（换预测器改善 18~56%，换补值方法 <5%） | 强：R1 消融实验 |
| C3 | 补值好 ≠ 预测好（CoIFNet 补值 MSE 最高 1.9，预测 MSE 接近最优） | 强：R2 组 F 进一步验证 |
| C4 | 两阶段方法在 Traffic（862 通道）上优势最大（领先 19~45%） | 强：所有缺失感知方法在高维上一致失败 |

### 1.2 条件性修正（R2 新发现）

| 编号 | R1 结论 | R2 修正 | 条件 |
|---|---|---|---|
| M1 | 缺失感知方法全面落后 | MissTSM-full 在 Electricity 反超 | 中维（321 通道）+ skip connection |
| M2 | 缺失感知方法全面落后 | CoIFNet-full 在 Weather 高缺失率反超 | 低维（21 通道）+ 缺失率 ≥50% |
| M3 | 加掩码反而损害性能 | 完整版 MissTSM 掩码有正效（Weather -7.8%） | 低维 + skip connection 配合 |
| M4 | — | 存在"缺失率阈值"：约 30~50% 是反转分界点 | 仅 Weather 验证，Traffic 不成立 |

### 1.3 未解决的核心矛盾

**缺失感知方法在理论上应优于两阶段方法**（联合优化的互信息下界严格高于串行流水线，CoIFNet 论文有形式化证明），但实验中仅在窄条件下成立。这个理论与实践的 gap 是后续研究的核心问题。

## 二、代码级根因分析

通过对 `src/models/` 下各模型源码的逐行审查，并与论文原始仓库（CRIB: github.com/Muyiiiii/CRIB，MissTSM: github.com/abhilash-neog/SparseTimeSeriesModeling，CoIFNet: github.com/KaiTang-eng/CoIFNet）逐一对比验证，发现的问题分为两类：**移植中引入的偏差**和**原始设计本身的局限**。

### A. 移植中引入的偏差（与原始论文代码不符）

#### A1. CRIB：位置编码退化使用

**当前实现**：`crib.py:374` 中 `pos_bias = self.pos_embed.pe[0, :PL, 0]`——只取 PE 矩阵的第一列作为标量，广播到 `(B, P, C, PL)`。

**原始代码**：将输入 reshape 为 `(B, P*N, L)` 后做 `x + self.enc_pos_embed(x)`，使用完整的 `pe[:, :P*N, :L]` 二维切片。每个 patch-channel token 获得一个完整 L 维的 sin/cos 编码向量。

**影响**：中等。原始代码对每个 token 分配了包含多频率信息的完整位置编码，而当前实现仅加了一个标量偏置，丢失了 patch 内位置的频率结构。这可能影响 TCN 编码后 Transformer 对 patch 间关系的建模能力。

#### A2. CoIFNet：架构重构导致参数差异

**当前实现**：用独立的 `nn.Linear(2C + time_feat, hidden=128)` embedding 层做一步压缩，backbone 在 hidden=128 维度上操作。

**原始代码**：没有独立 embedding 层。压缩发生在 SharedModule 第一层的 inter_model（TSBlock）中，且 **hidden=256**（非 128）。实际路径为 `TSBlock: Linear(2C+16, 256*2) → GEGLU → Linear(256, C)`，是渐进式压缩而非单步压缩。

**影响**：**高**。这导致两个关键差异：(1) hidden 维度 128 vs 256，当前实现信息容量减半；(2) 单步 Linear 压缩 vs GEGLU 门控渐进压缩，后者能选择性保留重要通道信息。对 Traffic (C=862)，原始路径为 1740→512→GEGLU→256→862，当前路径为 1740→128（13.5:1 压缩比 vs 原始的渐进压缩）。**这很可能是 CoIFNet 在 Traffic 上表现不佳的主要原因之一。**

#### A3. CoIFNet：输入拼接方式差异

**当前实现**：`x_full = x_normed * mask`（先乘 mask 再与 mask 拼接）。

**原始代码**：`torch.concat([x, mask], dim=-1)`（直接拼接 x 和 mask，不做 `x*mask`）。

**影响**：低。因为缺失位置的值通常已在数据集层面置零，`x*mask` 是冗余操作，语义上不改变结果。但严格说与原始代码不符。

### B. 原始设计本身的局限（忠实移植，问题来自论文原始代码）

#### B1. CRIB：z 变量未参与预测路径

**现象**：`crib.py:410` 中 `pred = self.pred_head(enc_out_1)`，预测头接收的是 Transformer 编码器输出 `enc_out_1`，而非变分采样 `z = qz_1.rsample()`。

**原始代码验证**：原始仓库 `CRIB.py` 中确认 `preds = self.predictor(enc_out_1)`，`z` 仅用于 KL 散度计算。甚至原始代码中有一行被注释掉的 `# py_z = self.predictor_2(z)`，说明作者曾考虑让 z 参与预测但最终放弃了。

**影响**：这意味着 CRIB 论文的核心贡献（信息瓶颈正则化）的梯度未流经预测路径。IB 约束仅通过 KL 项间接影响编码器表征，但预测头直接使用未经 IB 压缩的 enc_out。**这是一个值得探索的改进方向**——让预测头接收 z 可能释放 IB 的真正潜力，但也可能因过度压缩而损害性能（原始作者注释掉该路径可能正是因此）。

#### B2. CRIB：MultivariateNormal 的计算效率问题

**现象**：使用 `MultivariateNormal(loc, covariance_matrix=torch.diag_embed(scale))` 创建对角协方差矩阵。PyTorch 的 KL 散度实现走全矩阵路径（Cholesky 分解），复杂度 O(D^3)。

**原始代码验证**：原始仓库确认使用了完全相同的 `MultivariateNormal + diag_embed` 写法。

**影响**：数学上等价于 `Normal(loc, scale.sqrt())` 的独立高斯分布，KL 有解析式 `0.5*(loc^2 + scale - 1 - log(scale))`。替换后计算量降低约两个数量级，不改变数值结果。这是原始代码的一个效率问题，可以安全优化。

#### B3. MissTSM：单一共享 query 的容量瓶颈

**现象**：`misstsm.py:70` 的 `var_query = nn.Parameter(torch.zeros(1, 1, q_dim))` 是全局共享的单一 64 维向量，所有时间步用同一个 query 做跨变量聚合。

**原始代码验证**：论文明确写道 query Q ∈ R^{1×D}，"independent of variates and time-steps"。这是 MissTSM 相对于 mTAN 的刻意设计差异——用时间无关的共享 query 换取更强的泛化性。

**影响**：在低维数据集（Weather, C=21）上这个设计工作良好。但在 Traffic (C=862) 上，64 维 query 要从 ~600 个 key-value 对中提取信息并投影回 862 维，信息通道严重不足。**这是该方法在高维场景下性能下降的架构级原因**，可通过多 query 或条件化 query 来改进。

#### B4. MissTSM：skip connection 的信息浪费

**现象**：`feat = mask * x + (1-mask) * feat` 中，MissTSMLayer 对有观测位置也做了完整的跨变量注意力计算，但 skip 直接用原始值覆盖，该部分计算结果被丢弃。

**原始代码验证**：原始仓库的 shell 脚本中有 `--skip 1` 标志，确认这是论文的 MissTSMSkip 变体的设计。

**影响**：计算效率的浪费，同时也错失了利用跨变量信息增强已观测位置表征的机会。可探索加权融合策略 `feat = mask*(alpha*x + (1-alpha)*feat) + (1-mask)*feat`。

#### B5. iTransformer 与 MissTSM 的归一化不一致

**现象**：MissTSM 内部调用 iTransformer 时传 `use_norm=False`（因 MissTSMLayer 已做 RevIN），但 MissTSMLayer 的输出是反归一化后的原始值域。iTransformer 的 value_embedding 直接对原始尺度做线性变换，对数值范围大的数据集（Traffic/Electricity）可能训练不稳定。

**影响**：这是两个独立模块组合时产生的接口问题，原始 MissTSM 论文未讨论（其默认 backbone 也是 iTransformer，应存在同样的问题）。

## 四、问题诊断：为什么缺失感知方法在高维上失败？

综合代码分析和文献，我们可以归纳出三个层次的原因：

### 4.1 架构层：信息瓶颈（非 IB 意义上的）

所有缺失感知方法都存在维度压缩问题：

| 方法 | 压缩路径 | Weather (C=21) | Electricity (C=321) | Traffic (C=862) |
|---|---|---|---|---|
| CoIFNet（当前移植） | Linear(2C, 128) 单步压缩 | 50→128 (扩展) | 650→128 (5:1) | 1740→128 (13.6:1) |
| CoIFNet（原始代码） | TSBlock(2C+16, 256) GEGLU 渐进压缩 | 58→256 (扩展) | 658→256 (2.6:1) | 1740→256 (6.8:1) |
| MissTSM | 64-dim query → C-dim output | 21→64→21 (宽裕) | 321→64→321 (瓶颈) | 862→64→862 (严重瓶颈) |
| CRIB | Transformer(P×C tokens) | P×21=168 tokens | P×321=2568 tokens | P×862=6896 tokens (OOM) |

**关键洞察**：两阶段方法不存在这个问题。iTransformer 将每个变量作为独立 token，变量数 = token 数，attention 矩阵随 C 自然扩展，无信息压缩。注意当前 CoIFNet 移植的压缩比（13.6:1）远高于原始代码（6.8:1），这是移植偏差 A2 的直接后果。

### 4.2 优化层：联合目标的干扰

缺失感知方法的损失函数包含补值项和预测项：`L = L_pred + alpha * L_impute`。在高维数据上：
- L_impute 的梯度方差随 C 增大（更多缺失位置 → 更多梯度来源）
- L_pred 和 L_impute 可能产生梯度冲突（补值需要平滑，预测需要捕捉突变）
- 两阶段方法将优化完全解耦，避免了这种冲突

### 4.3 数据层：线性插值在低缺失率下的充分性

线性插值在随机点缺失 10~30% 时的补值质量足够好——缺失点两侧通常有近邻观测值，插值误差小。iTransformer 的 attention 机制能进一步修正插值偏差（因为它看到了跨变量信息）。只有当缺失率高到插值产生大量伪造值时，缺失感知方法的优势才能体现。

## 五、可行优化方向（按优先级排序）

### 方向 A：修复 CoIFNet 移植偏差（低成本，高优先级）

- **改什么**：将 hidden 从 128 改为 256（与原始代码一致），还原 TSBlock 渐进压缩架构（去掉独立 embedding 层），修正输入拼接为 `cat([x, mask])` 而非 `cat([x*mask, mask])`
- **预期收益**：CoIFNet 在 Electricity/Traffic 上的性能应有显著改善（当前 hidden=128 的压缩比是原始的 2 倍）
- **代码改动量**：~30 行
- **实验量**：对 Weather/Electricity/Traffic 跑组 A 子集即可验证（约 32 条实验）

### 方向 B：修复 CRIB 位置编码 + 效率优化（低成本，中优先级）

- **改什么**：(1) 位置编码改为原始代码的完整 2D 切片用法；(2) `MultivariateNormal` 替换为 `Normal`，解析 KL
- **预期收益**：位置编码修复可能改善 CRIB 的序列建模能力；Normal 替换降低计算开销但不改变数值结果
- **代码改动量**：~15 行

### 方向 C：探索 CRIB 的 z-conditioned 预测路径（中等成本，探索性）

- **改什么**：让预测头接收 z（rsample 的输出）而非 enc_out，实现原始作者注释掉的 `predictor_2(z)` 路径
- **性质**：这不是修复 bug，而是**改进原始设计**——原始作者可能因为 z 路径效果不好而放弃，但配合 beta-VAE 式的 KL 权重调控可能释放 IB 的潜力
- **风险**：原始作者注释掉该路径可能是有原因的（IB 过度压缩损害预测），需要 beta 搜索验证
- **实验量**：32 条基础 + 128 条 beta 搜索（条件触发）

### 方向 D：改进 MissTSM 的跨变量聚合机制（中等成本，中高潜力）

三个子方向：
- **D1**：时间步条件化 query（`q = var_query + time_proj(pos[t])`）
- **D2**：多 query 机制（K=8~16 个 learnable queries）
- **D3**：加权融合替代硬 skip（`alpha*x + (1-alpha)*feat`，alpha 可学习）

预期：D1/D2 可能改善连续片段缺失的表现（当前模型对缺失段的时间位置信息不敏感），D3 可能改善有观测位置的特征质量。

### 方向 E：将掩码信息注入 iTransformer（低成本，探索性）

当前两阶段方法的 iTransformer 完全不知道哪些位置是插值的。如果在 iTransformer 的输入中拼接 mask（类似 CoIFNet 的做法），但保持两阶段流水线（先插值再预测），可能兼得两者优势：
- 保留 iTransformer 的变量 token 化优势
- 让模型知道哪些位置不可信

这是一个"轻量级缺失感知"方向，介于纯两阶段和端到端之间。

### 方向 F：引入新基线方法（中等成本，丰富对比）

仓库中已有但未实验的论文：
- **S4M**（ICLR 2025）：非 Transformer 端到端，双流设计
- **GinAR**（KDD 2024）：图结构约束，针对变量级缺失
- **Merlin**：多视图表示学习

选择性引入 1~2 个作为额外基线，丰富方法对比维度。

### 方向 G：不确定性感知预测（高成本，理论导向）

受 UASA 论文启发，在缺失感知模型中引入不确定性量化：对插补值附加不确定性权重，让预测器对高不确定性位置降权。这需要较大的架构改动，但理论价值高。

## 六、总结

### 当前研究的核心价值

1. **系统性高维评测**：在 C=321/862 上评测缺失感知方法，填补文献空白
2. **量化的条件边界**：给出"缺失率×维度"的方法选择矩阵
3. **实现简化的影响量化**：R1 vs R2 的对比数据

### 最有价值的下一步

**方向 A（修复 CoIFNet 移植偏差）是最高优先级**——hidden=128 vs 原始 256 的差异可能直接解释 CoIFNet 在高维上的失败，修复后需要重新评估结论。**方向 B（修复 CRIB 位置编码）和方向 E（mask-aware iTransformer）** 是成本低、可并行推进的方向。方向 C（CRIB z 路径探索）和方向 D（MissTSM 改进）是面向创新的改进方向。

### 风险提示

- 方向 A 修复后 CoIFNet 可能仍不如两阶段——即便压缩比降低，联合优化的梯度冲突问题仍在
- 方向 C 的 z 路径被原始作者弃用，可能确实因 IB 压缩损害预测
- 方向 E 可能发现"mask 信息对强预测器帮助有限"（类似 R1 的掩码消融结论）
