# 实验计划 0718：面向块缺失的 HD-TTS × BiTGraph 融合优化实验

> 承接：`实验计划0715.md`、`0715复现实验报告.md`、`0715_BiTGraph_HDTTS结合方案.md`。  
> 计划日期：2026-07-18  
> 核心目标：以**块缺失（block missing）**为主场景，在统一 `window/seq_len=24`、`horizon/pred_len=24` 的公平预测长度下，重跑 BiTGraph 与 HD-TTS 基线，并验证一种以 HD-TTS 为主干、引入 BiTGraph 式 mask-biased graph refinement 的块缺失优化架构。

---

## 一、背景与本轮目标

### 1.1 0715 实验的关键结论

0715 复现实验已经确认：

1. **BiTGraph 在随机点缺失下稳定**：METR-LA、PEMS-BAY、Electricity 的 60%/80% random point missing 结果与论文数值高度接近，说明其 mask-biased graph convolution 对随机点缺失有效。
2. **HD-TTS 在块缺失下明显更稳**：在 50%-80% temporal block missing 下，HD-TTS 的 MAE 退化约 5%-8%，而 BiTGraph 退化约 32%-41%。
3. **两者机制互补**：
   - BiTGraph 更擅长“同一时间步仍有部分变量观测”时的跨变量补偿。
   - HD-TTS 更擅长“连续时间段整体缺失”时的跨时间尺度补偿。
4. **0715 的一个重要 caveat**：BiTGraph 使用 `seq_len=24/pred_len=24`，HD-TTS 使用 `window=24/horizon=12`。这是忠于两篇论文原始设置的复现方式，但不适合作为后续方法比较的公平协议。

### 1.2 本轮核心前提

本轮研究场景明确为：

> **高维多变量时间序列在高比例块缺失，尤其 temporal block / spatiotemporal block 条件下的预测。**

因此本轮不是继续平均关注点缺失和块缺失，而是把优化目标收束为：

> **在块缺失下优先超过 HD-TTS，同时尽量不牺牲随机点缺失下的稳定性。**

### 1.3 本轮必须修正的公平性问题

本轮所有主实验统一：

| 项目 | 统一设置 |
|---|---|
| 观测长度 | `window = seq_len = 24` |
| 预测长度 | `horizon = pred_len = 24` |
| 主数据集 | METR-LA、PEMS-BAY |
| 主缺失类型 | temporal block、spatiotemporal block |
| 辅助缺失类型 | random point |
| 主缺失率 | 30%、50%、60%、70%、80% |
| 评估指标 | MAE、MSE/RMSE、MAPE/MRE、训练时间、显存、参数量 |

其中 30% 用于观察中等块缺失下是否已经有收益，50%-80% 用于延续 0715 的高缺失率压力测试。

### 1.4 batch-size 调整原则

0715 实验中 A800 80GB 显存占用很低：

- BiTGraph：约 2.2-2.8GB。
- HD-TTS：约 5.7GB。

本轮 GPU 环境为 A800 80GB，1-7 号卡空闲，因此本轮需要显式提高 batch size，提高吞吐并减少训练时间。但 batch size 改变会影响优化动态，所以不能直接盲目调到最大。本轮采用：

1. 先做 batch-size sweep；
2. 选择“显存利用明显提高、速度提升明显、验证 MAE 不劣化超过 1%”的 batch size；
3. 所有主实验固定使用选定 batch size；
4. 若某数据集或模型 OOM，则只对该组回退一档，并在 `efficiency.csv` 中记录。

### 3.2 环境依赖策略

本轮采用“两套 baseline 环境 + 一个融合实现环境”的策略：

1. **BiTGraph baseline 继续使用 0715 的 `bitgraph` 环境**，用于公平重跑 BiTGraph 24→24 baseline。

- BiTGraph 官方依赖较旧，`torch==1.8.0+cu111` 已在 0715 验证可用，适合忠实重跑 baseline。

- 跨 conda 环境互相 import 不稳定，也不利于复现实验记录；本轮只允许“代码逻辑移植”，不允许运行时跨环境调用。

### 4.1 目标

在不明显牺牲验证 MAE 的前提下，充分利用 A800 80GB 显存，提高吞吐。

### 4.2 探测范围

| 模型 | 数据集 | 缺失类型 | 缺失率 | 候选 batch size |
|---|---|---|---:|---|
| BiTGraph | METR-LA | temporal_block | 0.5 | 64, 128, 256, 512 |
| BiTGraph | PEMS-BAY | temporal_block | 0.5 | 64, 128, 256, 512 |
| HD-TTS | METR-LA | block_t | 0.5 | 64, 128, 256, 512 |
| HD-TTS | PEMS-BAY | block_t | 0.5 | 64, 128, 256, 512 |
| Fusion | METR-LA | block_t | 0.5 | 64, 128, 256 |
| Fusion | PEMS-BAY | block_t | 0.5 | 64, 128, 256 |

每个候选只跑：

```text

train_batches=50
```

用于测量：

- 是否 OOM；
- peak GPU memory；
- sec/epoch；
- samples/sec；
- 初期 val MAE 是否异常；
- skipped batch ratio；
- 是否出现 NaN。

### 4.3 默认目标 batch size

若探测无异常，本轮默认采用：

| 模型 | 目标 batch size |
|---|---:|
| BiTGraph | 256 |
| HD-TTS | 128 |
| Fusion | 128 |

如果显存仍低于 30GB 且速度继续线性提升，可尝试：

| 模型 | 可升级 batch size |
|---|---:|
| BiTGraph | 512 |
| HD-TTS | 256 |
| Fusion | 256 |

但主实验不建议每个模型使用不同的 batch size 做性能结论比较。建议分两类记录：

1. **accuracy protocol**：固定 batch size，例如 128，用于比较 MAE。
2. **throughput protocol**：使用各模型最大稳定 batch size，用于比较效率。

### 4.4 学习率规则

第一轮不做线性学习率缩放，统一保持：

```text

```

如果 batch size ≥256 时出现验证 MAE 明显变差，再补一个 large-batch tuning：

| batch size | lr 候选 |
|---:|---|
| 256 | 0.001, 0.0015, 0.002 |
| 512 | 0.001, 0.002, 0.004 |

最终报告必须区分“batch size 影响”和“模型结构影响”。

## 六、Phase 3：融合模型设计

### 6.1 模型定位

本轮融合模型不定义为“BiTGraph + HD-TTS 平等拼接”，而定义为：

> **Block-aware HD-TTS 主干增强模型：以 HD-TTS 的多尺度时间补偿为核心，在块缺失边界和粗尺度表示中引入 BiTGraph 式 mask-biased graph refinement。**

推荐命名：

```text
Block-HMBGNet
```

全称：

```text
Block-aware Hierarchical Mask-Biased Graph Network
```

### 6.2 总体结构

输入：

```text
X ∈ R^{B×T×N×C}
M ∈ {0,1}^{B×T×N×C}
T=24, horizon=24
```

结构：

```text
1. HD-TTS Encoder
   X, M, node embedding, time covariates -> H_0

2. Temporal downsampling backbone
   H_0 -> H_1 -> H_2 -> ... -> H_L

3. Block mask statistics encoder
   M -> block length / observed ratio / boundary distance / per-node density

4. Coarse-scale mask-biased graph refinement
   H_s, M_s -> G_s, for s >= 1

5. Boundary-aware fine-scale graph refinement
   H_0 -> H_0 + b_t * GraphRefine(H_0)

6. Block-aware scale gate
   α_s = Gate(mask_statistics)

7. Decoder
   Z = Σ_s α_s · G_s
   Z -> Y_hat ∈ R^{B×24×N×C}
```

### 6.3 模块 A：BlockMaskEncoder

从输入 mask 中提取块缺失结构特征。

建议输出：

| 特征 | shape | 含义 |
|---|---|---|
| `observed_ratio_t` | `[B,T,1,1]` | 每个时间步全节点观测比例 |
| `observed_ratio_n` | `[B,1,N,1]` | 每个节点窗口内观测比例 |
| `global_observed_ratio` | `[B,1,1,1]` | 整个窗口观测比例 |
| `max_missing_run` | `[B,1,N,1]` 或 `[B,1,1,1]` | 连续缺失长度 |
| `boundary_distance` | `[B,T,N,1]` | 距最近观测边界的距离 |
| `block_center_score` | `[B,T,N,1]` | 是否处在缺失块中心 |

其中 `boundary_distance` 对本轮很关键：

```text
靠近块边界：细尺度信息和 graph refinement 仍可能有用
块中心：更依赖 coarse temporal scale
```

### 6.4 模块 B：Boundary-aware graph refinement

BiTGraph 式 graph refinement 不应在所有时间点同等强度使用，而应主要作用在块缺失边界。

定义：

```text
b_t = exp(-distance_to_observed_boundary / τ)
H'_0 = H_0 + b_t * MaskBiasedGCN(H_0, M)
```

直觉：

- 块边界附近，前后观测可提供局部趋势，graph refinement 有用。
- 块中心处，原始尺度缺失严重，graph refinement 容易传播空信息，应自动减弱。

### 6.5 模块 C：Coarse-scale mask-biased graph refinement

在 HD-TTS 的中粗尺度表征上引入 mask-biased graph：

```text
G_s = MaskBiasedGCN(H_s, M_s, A_base, A_adaptive), s >= 1
```

其中：

```text
A_eff = A_base + A_adaptive + β · A_mask_bias
```

建议：

- `A_base` 使用 DCRNN 距离图；
- `A_adaptive` 使用可学习节点嵌入；
- `A_mask_bias` 使用 BiTGraph 的“观测更充分节点向缺失更严重节点传播更强”的方向性思想；
- 先只在 coarse scale 使用，避免原始尺度全缺失时传播无意义信息。

### 6.6 模块 D：Block-aware scale gate

这是本轮最重要的创新点。

普通 HD-TTS 的 attention 已经能隐式选择尺度，但本轮希望显式加入块缺失结构：

```text
α_s = softmax(MLP([z_s, observed_ratio_s, boundary_distance_s, max_missing_run]))
```

预期行为：

| 缺失状态 | scale gate 应倾向 |
|---|---|
| 短块缺失 | 细尺度 + 中尺度 |
| 长块缺失 | 中粗尺度 + 粗尺度 |
| 块边界 | 细尺度 + boundary graph |
| 块中心 | 粗尺度 temporal context |
| 随机点缺失 | 细尺度 + graph refinement |

### 6.7 第一版实现建议

第一版不要一次性做太复杂。建议按以下递进实现：

| 版本 | 内容 | 目的 |
|---|---|---|
| `hdtss_h24` | 原 HD-TTS，horizon=24 | 公平 baseline |
| `block_hmbg_v1` | HD-TTS + BlockMaskEncoder + block-aware scale gate | 验证显式块结构 gate 是否有效 |
| `block_hmbg_v2` | v1 + coarse-scale mask-biased graph | 验证粗尺度空间传播是否有效 |
| `block_hmbg_v3` | v2 + boundary-aware fine-scale graph | 验证边界 graph refinement 是否有效 |

主报告中如果 v3 最优，可把 v2/v1 作为 ablation。

## 九、验收标准

### 9.1 基线重跑验收

| 项目 | 标准 |
|---|---|
| HD-TTS horizon=24 | METR-LA/PEMS-BAY block_t/block_st 全部跑通 |
| BiTGraph batch size | `--batch_size` 实际影响 DataLoader，日志记录 batch size |
| 统一协议 | 所有主表均为 24→24，不混入 0715 horizon=12 结果 |
| 大 batch | 至少较 0715 默认 batch size 提高 4× 或给出 OOM/退化原因 |
| 多 seed | 主结论相关配置至少 3 seeds |

### 9.2 融合模型验收

Block-HMBGNet 需要满足：

1. 在 block_t 0.7/0.8 上，至少一个数据集显著优于 HD-TTS-AMP，且另一个数据集不明显退化。
2. 在 block_st 0.7/0.8 上，平均 MAE 不劣于 HD-TTS-AMP。
3. random_point 0.7/0.8 上相对 HD-TTS-AMP 退化不超过 2%。
4. gate 行为符合预期：
   - 块中心 coarse gate 更高；
   - 块边界 fine/boundary graph 权重更高；
   - random point 下 graph refinement 权重不被完全压到 0。
5. 消融能说明至少一个新增模块是必要的。

### 9.3 如果融合模型不优于 HD-TTS

如果 Block-HMBGNet 未超过 HD-TTS，则不能简单判失败，需要做如下归因：

| 现象 | 可能原因 | 下一步 |
|---|---|---|
| 所有块缺失都退化 | graph 分支引入噪声 | 减小 graph 容量、加 gate 正则 |
| block_t 有收益，block_st 无收益 | 空间传播和 HD-TTS 原空间池化冲突 | 只保留 temporal/block gate |
| 只有 0.3/0.5 有收益，0.8 无收益 | 极端块中心无信息，graph 无用 | 加强 coarse temporal loss |
| gate 不分边界/中心 | mask statistics 不足或未被用到 | 加 auxiliary gate supervision |
| batch size 变大后性能下降 | 优化动态变化 | 调小 lr 或加 warmup |

## 十一、预期结论形式

本轮实验结束后，希望能回答：

1. 在统一 24→24 预测长度下，HD-TTS 是否仍然在块缺失下明显优于 BiTGraph？
2. 增大 batch size 后，两个 baseline 的速度、显存、精度是否稳定？
3. Block-HMBGNet 是否能在 temporal block / spatiotemporal block 下超过 HD-TTS？
4. 如果超过，是来自：
   - block-aware scale gate；
   - coarse-scale mask-biased graph；
   - boundary-aware graph refinement；
   - 还是单纯参数量增加？
5. 融合模型是否保持 random point 下的稳定性？
6. gate 是否学到了符合直觉的行为：块中心看粗尺度，块边界看细尺度/graph？

理想结论：

> 在统一 24 步预测长度下，HD-TTS 仍是块缺失强 baseline；进一步引入 block-aware scale routing 与 coarse-scale mask-biased graph refinement 后，模型在 70%-80% temporal/spatiotemporal block missing 下获得稳定收益，同时 random point missing 不明显退化。这说明面向块缺失的关键不是无差别强化图传播，而是让图传播只在有空间补偿价值的尺度和边界处工作。

如果没有超过 HD-TTS，也可以形成负结论：

> 在块缺失主场景下，HD-TTS 的多尺度时间补偿已经捕获了主要有效信息，额外的 mask-biased graph refinement 在当前设计下未带来稳定增益；后续应优先改进 block-aware temporal routing，而不是增加跨变量图模块。
