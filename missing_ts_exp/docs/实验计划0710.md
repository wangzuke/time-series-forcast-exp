# 实验计划 0710：MissTSM 分组 Query 的图方法式改进（观测相关性动态重分组 + 预定义先验/自适应路由融合）

> 承接《0709实验报告.md》遗留问题，以及对缺失值预测论文集（`papers/missing-value-forecasting/`）中 GinAR、IBN 图方法机制的调研启发。
> 计划日期：2026-07-10
> 核心目标：把 0709 中方案 A（相关性预分组）与方案 B（可学习软路由）的对立选择，改造为图方法领域已验证有效的两条思路——**(1) 用观测数据动态估计相关性，而非训练前用完整数据算一次固定值**；**(2) 预定义先验图与自适应图融合使用，而非二选一**——分别验证能否解决 0709 报告遗留的两个开放问题。

---

## 一、背景回顾

### 1.1 0709 报告的核心结论与遗留问题

《0709实验报告.md》验证了两条"自动分组"路径，结果并不理想：

1. **方案 A（相关性预分组，`grouped_q4_corr`）未达成目标**：Traffic 上不仅没有解决 `grouped_q4`（序号切分）的不稳定问题，随机点缺失下反而进一步退化（相对 `full` 最差达 -10.2%）；Weather 的 `continuous_segment` 条件下也出现了计划外的退化（50%/70% 缺失率退化 4.8%/3.2%）。
2. **方案 B（可学习软路由，`grouped_q4_soft`）基本达成 Traffic 稳定性目标**（相对 `grouped_q4` 改善 0.9%~4.3%），但训练时间开销远超预期（平均 +52.9%，最高 +146.1%），且由于未保存 checkpoint，**路由是否学到有意义的分组结构完全无法验证**（0709报告 §3.5）。
3. **两个新方案在 Weather 的 `continuous_segment` 条件下都出现退化**，报告 §4.3 建议 2 明确提出这是一个未解决的开放问题：怀疑是"静态/训练期分组"与"连续片段缺失"之间存在系统性不匹配，建议下一轮把相关矩阵改为**只用连续片段缺失注入后的观测数据计算**，而非完整训练序列，以此定位问题根源。

### 1.2 论文调研带来的两点启发

在完成 0709 实验后，我们系统阅读了缺失值预测论文集中使用图方法的两篇论文——**GinAR**（`06_GinAR_...pdf`）和 **IBN**（`08_IBN_...pdf`，GinAR 的改进版）——发现 0709 的方案 A/B 分别对应图方法里的"预定义图"和"自适应图"，而这两篇论文的核心经验恰好可以直接回应 0709 的两个遗留问题：

**启发 1：预定义图和自适应图从来不是二选一，而是加权融合使用。**

GinAR 的 Adaptive Graph Convolution（AGCN）明确是两路融合（原文公式 7）：

```
Z = FLN( A_pre · X · W1 + b1  +  A_adap · X · W2 + b2 )
```

其中 `A_pre` 是训练前基于先验知识（道路距离或皮尔逊相关系数）确定的固定图，`A_adap` 是训练中端到端学出的自适应图，`W1`/`W2` 是各自独立的可学习权重矩阵，两路结果相加融合，而不是只用其中一个。IBN 沿用了同样的融合结构（只是把 `A_adap` 换成了基于欧氏距离的高斯核动态图 `A_Gau`）。

**这跟 0709 方案 A、方案 B 的关系是同构的**：`grouped_q4_corr` 就是"预定义图"路线（训练前离线算好、固定不变），`grouped_q4_soft` 就是"自适应图"路线（训练中端到端学习）。0709 报告把两者当作互斥的候选方案对比、二选一，但论文的经验是两者应该**融合**——用预定义图给自适应图一个可靠的先验方向，同时保留自适应图的纠错空间。

**启发 2：预定义图的构建方式，IBN 明确批评了"训练前一次性算好、之后不变"这种做法不够灵活。**

IBN 论文批评 GinAR 的自适应图"直接用一个变量嵌入矩阵学出来，可解释性差、不稳定"，转而在 GGCN 模块里**用当前的、实时的节点特征算欧氏距离来构图**，而不是像预定义图那样一次性算好、之后再也不变。虽然 IBN 针对的是自适应图本身，但这个"让图结构能反映当前实际观测状态，而非训练前的静态先验"的原则，正好可以用来回应 0709 报告 §4.3 建议 2 提出的开放问题：**方案 A 的相关矩阵是用"完整、无缺失的训练序列"一次性算出来的，这个相关性结构在实际推理时（尤其是连续片段缺失）可能早已不成立**。

### 1.3 本轮要验证的两个假设

| 假设 | 对应 0709 遗留问题 | 验证方式 |
|---|---|---|
| **假设 D**：用"观测到的（含缺失）数据"而非"完整训练序列"计算相关性，能否消除 Weather `continuous_segment` 的退化，同时改善 Traffic 的不稳定性 | §4.3 建议 2 | 新变体 `grouped_q4_corrobs` |
| **假设 E**：把方案 A（预定义相关性图）和方案 B（自适应路由）融合使用，而不是二选一，能否同时拿到"方案 A 的零成本先验"和"方案 B 的 Traffic 收益"，比单独用任何一个都更好 | 隐含于 §4.2 第 6 条"方案 A/B 性价比对比" | 新变体 `grouped_q4_fuse` |

## 二、方案 D：基于观测数据的动态相关性重分组

### 2.1 设计原理

0709 方案 A（`compute_channel_order`，`src/data/grouping.py`）的相关矩阵计算方式是：

```python
values, _, n_features = _load_raw(dataset_name)
train_end, _, _ = _split_indices(dataset_name, len(values))
arr = values[:train_end]          # 完整训练序列，不含任何缺失
corr = np.corrcoef(arr, rowvar=False)
```

这算出来的是"这个数据集在完全没有缺失时，变量之间本来的相关性"。但实际训练和推理时，输入的历史窗口是**注入了缺失之后**的观测值——如果缺失类型是 `continuous_segment`（连续一段时间整个变量的观测消失），那么模型在推理时"能看到"的相关性结构，跟"完整数据算出来的相关性"很可能是脱节的：完整数据里两个变量原本高度相关，但如果其中一个变量恰好连续缺了一大段，训练时这段时间该变量根本没有值参与计算，"提前算好的强相关性"在这段时间可能名不副实。

方案 D 的做法：**按缺失类型和缺失率，先注入一次缺失，再用注入后的观测值（缺失位置按项目现有约定填 0，与 `MissTSMLayer._revin` 里 `x * mask` 的处理方式保持一致）计算相关矩阵**，之后复用方案 A 的层次聚类流程得到重排顺序。

需要说明的关键简化（诚实记录，避免后续误解）：

- 项目里训练阶段每个 epoch 的缺失掩码都会重新采样（`dataset.set_epoch_seed_offset(ep)`，见 `CLAUDE.md` §5），本方案不会、也不需要为每个 epoch 单独算一次相关矩阵——那样代价太高，也偏离了"预定义图"应有的"训练前离线算好、训练中固定"的定位。做法是**只用固定 mask 种子（`mask_seed=0`）实例化一次该 `(missing_type, missing_rate)` 组合的缺失掩码，套在完整训练序列上算一次相关矩阵**，把它当作"这一类缺失模式下，变量关系大致会是什么样"的一次代表性采样，而不是想要精确复刻每个 epoch 的具体掩码。
- 因此 `group_order` 现在的粒度是 `(dataset, missing_type, missing_rate)` 三元组，不再是 0709 里只按 `dataset` 缓存一份（一个数据集只有一个 order）。这是本方案与方案 A 相比**唯一的变量**，其余（G=4、连续切片逻辑、q_dim、训练超参）保持不变，确保是干净的单变量消融。

### 2.5 判定标准

- **主要判据（对应 Weather 退化根因排查）**：Weather 的 `continuous_segment` 条件下，`grouped_q4_corrobs` 相对 `grouped_q4_corr`（静态完整数据相关性）是否明显改善（≥3%），且不再劣于 `grouped_q4`（序号切分）。若改善明显，说明 0709 报告 §4.3 建议 2 的猜测成立——退化根源确实是"训练前用完整数据算的相关性"和"连续片段缺失下的实际观测状态"不匹配；若没有改善甚至更差，说明退化另有原因（比如分组机制本身与片段缺失的结构性冲突，而非相关矩阵计算方式），需要在报告里明确排除这条假设。
- **次要判据（Traffic）**：Traffic 上 `grouped_q4_corrobs` 相对 `grouped_q4_corr` 是否改善（尤其是随机点缺失场景，因为方案 A 在这个场景下退化最严重，见 0709 报告 §2.3 第 1 条）。
- **不要求 `grouped_q4_corrobs` 超过 `grouped_q4_soft`**——方案 D 本身仍是"预定义图"路线（零额外参数、训练中不再调整），核心目的是排查退化根因，不是要在绝对性能上压过方案 B。

## 三、方案 E：预定义先验 + 自适应路由融合

### 3.1 设计原理

参照 GinAR/IBN 的融合公式 `Z = A_pre·X·W1 + A_adap·X·W2`，把 0709 的方案 A（预定义相关性分组）和方案 B（自适应软路由分组）做成两条并行路径，各自算出一份分组注意力结果，再融合：

- **路径 A（预定义）**：复用 `grouped_q4_corr` 完全相同的硬切分逻辑——用相关性聚类得到的固定 `group_order` 重排通道后连续切片，每组独立 query 做交叉注意力。这一路和 0709 里的 `grouped_q4_corr` 在计算方式上完全一样。
- **路径 B（自适应）**：复用 `grouped_q4_soft` 完全相同的软路由逻辑——每个通道一个可学习身份向量 `channel_embed`，每组一个可学习原型向量 `group_proto`，`softmax` 出 (C, G) 归属权重，做软门控后每组对全部通道做交叉注意力。这一路和 0709 里的 `grouped_q4_soft` 在计算方式上完全一样。
- **融合**：两路各自得到 `(B*L, D)` 的分组注意力输出（拼接 G 组之后），分别过各自独立的线性层，再相加——对应 GinAR 公式里 `W1`、`W2` 各自独立学习"该给这一路多大权重"，而不是用一个固定标量做加权平均：

```python
attn_out_A = self.group_proj_A(torch.cat(group_outs_hard, dim=-1))   # 预定义图路径
attn_out_B = self.group_proj_B(torch.cat(group_outs_soft, dim=-1))   # 自适应图路径
attn_out = attn_out_A + attn_out_B                                    # 对应 GinAR: A_pre·X·W1 + A_adap·X·W2
```

**这跟 0709 报告里"方案 A 与方案 B 性价比对比、二选一推荐"的框架不同**：融合方案不需要判断"谁更好就用谁"，而是让模型自己在训练中决定"这个数据集/这个缺失场景下，更该依赖预定义先验还是自适应路由"——因为 `group_proj_A`、`group_proj_B` 的权重是分别学出来的，如果某个数据集上预定义图完全没用，模型理论上可以把 `group_proj_A` 的输出学成接近于 0（贡献很小），退化为近似只用自适应路径；反之亦然。

### 3.2 预期计算成本（需要在结果里如实记录）

0709 报告 §3.3 第 4 条已经发现方案 B 单独一路的训练时间开销就远超预期（平均 +52.9%，最高 +146.1%），本方案融合了方案 A（零额外开销）和方案 B（全通道注意力路径），**预期训练时间开销约等于方案 B 单独的开销，不会因为多了一路预定义分组而显著叠加**——因为预定义路径的硬切分注意力（每组只看 C/4 个通道）本身开销很小，真正的开销瓶颈来自方案 B 那条"每组看全部 C 个通道"的软路由路径，融合方案没有让这条路径变得更贵。但仍需要按项目一贯做法，在结果表里记录实测的单 epoch 训练时间，不能只凭预期推测下结论（0709 报告 §3.3 第 4 条已经是一次"计划预估 <5%、实测 +52.9%"的教训）。

参数量预期：在 `grouped_q4_soft` 已有的 `channel_embed (C, q_dim)` + `group_proto (G, q_dim)` 基础上，多一个 `group_proj_A`（大小与现有 `group_proj` 一致），Traffic 上参数增量预计与 0709 报告 §3.4 表格中 `grouped_q4_soft` 的 +12.51% 相近或略高（多了一个投影层，量级是 `q_dim × q_dim`，相对 862 通道的 `channel_embed` 矩阵不算大头）。

### 3.6 判定标准

- **有效性**：`grouped_q4_fuse` 是否在 3 个数据集上都不差于 `grouped_q4_corr` 和 `grouped_q4_soft` 中较优的那一个（即"融合至少不亏"），尤其关注 Traffic（方案 B 的强项）和 Weather 的 `random_point`（方案 A 尚可、方案 B 也尚可的场景）是否都能保住已有收益。
- **是否真的学到了"取长补短"**：如果某个数据集下 `grouped_q4_fuse` 明显优于方案 A、方案 B 单独使用时的最佳结果，说明融合确实起到了"各取所长"的作用；如果 `grouped_q4_fuse` 的结果始终约等于方案 A、方案 B 中较优的那个（没有超出两者的并集），说明融合只是"抄近路选到了较好的一个"，没有产生额外增益，这个区分需要在报告里明确指出，不能笼统地说"融合更好"。
- **成本是否可接受**：训练时间是否显著超过方案 B 单独的开销（如果远超预期，需要按 0709 报告 §4.3 建议 3 的思路，后续考虑对软路由路径做 top-k 稀疏化）。

## 四、方案 D + E 叠加（条件触发，Phase 3）

若方案 D（§二）证明"观测相关性"确实明显优于"静态完整数据相关性"（尤其是 Weather `continuous_segment` 退化被消除或显著缓解），则值得再跑一版**同时应用两个改进**的版本：用方案 D 的观测相关性替换方案 E 融合方案里预定义路径所使用的先验来源。

| 变体名 | 含义 |
|---|---|
| `grouped_q4_fuseobs` | G=4，融合方案（同 `grouped_q4_fuse`），但预定义路径使用方案 D 的观测数据相关性而非静态完整数据相关性 |

**代码改动**：只需要在 `MissTSMPipeline.__init__` 里，对 `grouped_q4_fuseobs` 这个变体名，把 `group_order` 的来源换成 `get_or_compute_channel_order_observed(cfg.dataset, cfg.missing_type, cfg.missing_rate)`（方案 D 新增的函数），`MissTSMLayer`/`MissTSMModel` 的分支逻辑无需改动（`_fuseobs` 后缀在 `MissTSMModel.__init__` 里按前缀匹配到 `_fuse` 分支，与 `_fuse` 共用同一套硬路径+软路径融合结构）。

**实验量**：1 变体 × 3 数据集 × 2 缺失类型 × 3 缺失率 × 2 种子 = 36 条（条件触发，是否跑视 Phase 1 结果决定）。

**触发条件**：Phase 1（方案 D）结果显示，在至少一个数据集上，观测相关性相对静态完整数据相关性有 ≥3% 的改善（对应 §2.5 判据），才执行 Phase 3；如果方案 D 本身没有验证出明显收益，直接跳过 Phase 3，不做无意义的排列组合。

## 六、风险与注意事项

1. **方案 D 的相关性计算仍然只用训练集数据**（完整训练序列 + 固定种子注入的一次缺失），不使用验证/测试集，与项目既有约定一致。
2. **方案 D 的"固定种子”选择需要与训练/推理时实际使用的种子（2024/2025）区分开**：`mask_seed=0` 只是为了得到一个"有代表性的缺失实例"来估计相关性，不代表 2024/2025 两个训练种子会用不同的 `group_order`——同一个 `(dataset, missing_type, missing_rate)` 组合下，两个训练种子复用同一份预计算好的观测相关性排列，这是有意为之的简化（否则每个训练种子都要单独算一次相关性，混入"随机性"这个新变量，污染对比的干净性）。
3. **方案 E 的训练时间、显存、参数量三项都要如实记录**，不能只看 MSE——0709 报告已经有一次"计划预估 <5%、实测 +52.9%"的教训，方案 E 是方案 B 的超集，成本只会更高不会更低，必须在报告里给出实测数字。
4. **方案 E 主实验（Phase 2）固定使用方案 A 的静态相关性作为预定义路径的先验**，不要在 Phase 2 里同时切换先验来源，否则无法区分"融合本身有没有用"和"先验来源好不好"这两个问题——这两者分别由方案 E（Phase 2）和方案 D+E 叠加（Phase 3）独立验证。
5. **不要同时改多个变量**：方案 D 只改"相关性计算所用的数据来源"，方案 E 只改"是否融合预定义与自适应两条路径"，其余（G=4、q_dim、num_heads、训练超参）都保持与 0709 现有变体完全一致。
6. **异常种子单独标注**：延续 R1-0709 的一贯做法，若某个 (数据集, 缺失率, 缺失类型) 组合两个种子结果差异很大，在汇总表中单独标记，不直接吞进均值。
7. **未经用户允许不要起训练**：本计划文档只是设计与代码改动说明，实际执行 Phase 0-3 的训练命令前需要征得用户同意（延续 `CLAUDE.md` §9 的既有约定）。

## 七、预期结论形式

本轮结束后，希望能回答：

1. **方案 D（观测相关性动态重分组）是否解决了 Weather `continuous_segment` 的退化问题**？如果解决了，说明 0709 报告 §4.3 建议 2 的猜测（"静态相关性与连续片段缺失的实际观测状态不匹配"）成立，为后续"分组机制需要感知当前缺失模式"这一设计原则提供直接证据；如果没有解决，说明退化另有更深层的原因（比如硬切分分组机制本身与片段缺失存在结构性冲突），需要在报告里如实记录这一负面结果，而不是勉强解释。
2. **方案 E（预定义先验 + 自适应路由融合）是否比单独使用方案 A 或方案 B 更好，还是只是"择优"而没有实质增益**？这决定了融合这条路径是否值得作为后续默认的分组机制。
3. **方案 E 的额外算力成本是否可接受**？如果收益有限但成本翻倍（叠加了方案 A 的可忽略开销和方案 B 的显著开销），需要明确指出"融合"在当前实现方式下性价比不如单独用方案 B。
4. **如果方案 D、E 都被验证有效，是否值得叠加（Phase 3）**，叠加后是否有 1+1>2 的效果，还是收益边际递减。
5. 是否需要进一步探索 0709 报告 §4.3 建议 3 提到的稀疏化路由（top-k 截断），以降低方案 E/方案 B 的计算开销——这个问题本轮不直接验证，但会根据方案 E 实测的训练时间数据，判断是否值得作为下一轮的独立课题。

结论将撰写为独立报告 `docs/0710实验报告.md`，风格与图表规划参照 `docs/0709实验报告.md`（含四变体/多变体 MSE 对比柱状图、改善率热力图、Traffic 专项对比图、稳定性对比图、训练时间对比图，视本轮新增变体数量调整图表数量）。
