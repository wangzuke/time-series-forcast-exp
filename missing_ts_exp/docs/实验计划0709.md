# 实验计划 0709：MissTSM Query 自动分组（相关性预分组 + 可学习软路由）

> 承接《0706实验报告.md》§6（P2-B：MissTSM 分组 query 消融）与《四轮实验综合总结报告.md》遗留问题 #5。
> 计划日期：2026-07-09
> 核心目标：把 `grouped_q4` 现有的"按通道序号均匀切分"替换为"数据驱动的自动分组"，验证能否在 Traffic（862 变量）等高维数据集上获得稳定收益，同时不破坏 Weather 上已经验证有效的表现（0.7%~9.3% 改善）。

---

## 一、背景回顾

### 1.1 现状问题

`MissTSMLayer`（`src/models/misstsm.py:146-162`）的 `grouped_q` 变体把 C 个通道按**固定连续序号**切成 G 组：

```python
group_size = (C + G - 1) // G
for g in range(G):
    c_start, c_end = g * group_size, min((g + 1) * group_size, C)
    emb_g = emb[:, c_start:c_end, :]   # 谁和谁同组，完全由通道在 CSV 里的列顺序决定
```

R4 实验（`0706实验报告.md` §6.2）显示：

| 数据集 | 变量数 | 每组约 | grouped_q4 vs full |
|---|---|---|---|
| Weather | 21 | 5-6 | 6/6 条件改善，0.7%~9.3% |
| Electricity | 321 | ~80 | 多数条件小幅改善 0.4%~1.6% |
| Traffic | 862 | ~215 | 不稳定：随机点 50% 退化 5.5%，连续片段 30% 改善 0.7% |

**关键诊断**：Weather 表现好很可能是巧合——CSV 列顺序恰好把物理相关的变量（温度类、风速类等）排在了一起；Traffic 的传感器编号和地理/交通关联性无关，序号切分等价于随机分组，所以效果不稳定。这一诊断已写入 R4 报告 §6.3 和综合报告遗留问题 #5，本计划是对该遗留问题的具体落地。

### 1.2 两条候选路径

上一轮讨论中给出的可行性分析，选定优先级最高的两条路径作为本轮实验对象：

| 方案 | 一句话 | 分组是否训练时学习 | 风险 |
|---|---|---|---|
| **方案 A：相关性预分组** | 训练前用变量相关系数聚类，把"谁和谁同组"这件事从"按序号"换成"按数据关联" | 否，训练前离线算好、训练中固定 | 低 |
| **方案 B：可学习软路由** | 每个变量学一个 identity 向量，G 个组学一个原型向量，用相似度动态决定每个变量对每组的贡献权重 | 是，随预测损失端到端学习 | 中 |

两者都保留 G=4（与现有 `grouped_q4` 直接可比），后续如果都验证有效，再考虑扩展到 G=8 或更大数据集专属的分组数。

## 二、方案 A：相关性预分组

### 2.1 设计原理

核心洞察：`grouped_q` 的分组循环本身不关心"组内通道的原始序号"，只关心"这组包含哪些通道的 embedding"。因此**不需要改动分组循环逻辑**，只需要在切片之前，把通道维度按"相关性顺序"重新排列一次，之后复用现有的连续切片代码。

具体做法（seriation / 领接排序）：

1. 用训练集上完整的（未注入缺失前的）原始序列，计算 C×C 皮尔逊相关系数矩阵。
2. 用 `1 - |corr|` 作为距离，做层次聚类（`scipy.cluster.hierarchy.linkage`，`method="average"`），并用 `optimal_leaf_ordering=True` 得到一个通道排列顺序 `perm`，使得相关性强的通道在这个排列里彼此靠近。
3. 训练/推理时，在 `emb = emb + pos_embed(emb)` 之后、分组切片之前，插入一行 `emb = emb[:, perm, :]`（`pad_mask` 同步重排），其余分组代码完全不变。

这样做的好处：
- **组大小依然严格均匀**（和现在的 `grouped_q4` 完全一致），不需要处理聚类导致的组大小不均问题。
- **不增加任何可学习参数**，训练稳定性和现有 `grouped_q4` 相同。
- 位置编码 `_PE2D` 是在重排**之前**按原始通道序号加的，所以每个通道的"身份编码"不受重排影响，重排只改变了"谁和谁分到一组"，不改变每个通道自身的表示。

### 2.2 代码改动清单

| 文件 | 改动 |
|---|---|
| 新建 `src/data/grouping.py` | `compute_channel_order(dataset_name, n_groups) -> List[int]`：加载训练集原始数据 → 相关矩阵 → 层次聚类 leaf order → 返回排列 |
| 新建 `scripts/precompute_group_order.py` | 对 Weather/Electricity/Traffic 离线跑一次，结果缓存为 `results_cache/group_order/{dataset}.json`（存完整排列，G 在模型侧切片时再决定分几组，不用重复计算） |
| `src/models/misstsm.py` | `MissTSMLayer.__init__` 新增 `group_order: Optional[List[int]] = None`；`variant == "grouped_q"` 分支里若传入 `group_order` 则先 `emb = emb[:, group_order, :]`、`pad_mask = pad_mask[:, group_order]` 再切片 |
| `src/training/pipelines.py` | `MissTSMPipeline` 初始化时按 `cfg.dataset` 读取缓存的 `group_order`，传给 `MissTSMModel` → `MissTSMLayer` |
| `src/training/run_forecast.py` | `--misstsm_variant` 增加 `grouped_q4_corr`、`grouped_q8_corr` 两个可选值 |

### 2.3 变体命名

| 变体名 | 含义 |
|---|---|
| `grouped_q4_corr` | G=4，相关性重排后连续切片 |
| `grouped_q8_corr`（备选，视 A 的 G=4 结果决定是否跑） | G=8，相关性重排 |

### 2.4 实验矩阵

与 R4 P2-B 完全对齐，便于直接和已有的 `grouped_q4`（序号切分）、`full`（单 query 基线）结果做三方对比：

| 维度 | 取值 |
|---|---|
| 数据集 | Weather, Electricity, Traffic |
| 缺失类型 | random_point, continuous_segment |
| 缺失率 | 0.3, 0.5, 0.7 |
| 预测长度 | 96 |
| 种子 | 2024, 2025 |

**实验量**：1 变体（`grouped_q4_corr`） × 3 数据集 × 2 缺失类型 × 3 缺失率 × 2 种子 = **36 条**。
`full` 与 `grouped_q4`（序号切分）复用 R4 已有结果，不重跑。

### 2.5 判定标准

- **主要判据**：Traffic 上 `grouped_q4_corr` vs `grouped_q4`（序号切分），MSE 改善 ≥3% 且 6 个条件中至少 5 个不劣于 `full` 基线（对照现有序号切分在随机点 50% 上退化 5.5% 的问题）。
- **次要判据**：Weather 上 `grouped_q4_corr` 不应比现有 `grouped_q4`（已知有效）明显变差，允许小幅波动（<1%），否则说明 Weather 原有的优势确实主要来自"CSV 列顺序恰好接近物理分组"这一巧合，重排反而打乱了它。
- 若 Traffic 显著改善但组内变量数依然是瓶颈（~215 个/组），可作为后续把 G 调大（如 Traffic 用 G=16）的证据。

## 三、方案 B：可学习软路由

### 3.1 设计原理

给每个通道一个**可学习的身份向量**，给每个组一个**可学习的原型向量**，用两者的相似度作为该通道对该组的"归属权重"，训练中随预测损失反向传播自动调整——这是训练过程中真正"自动"决定分组的路径。

具体设计：

```python
# 新增参数（MissTSMLayer.__init__，variant == "grouped_q_soft"）
self.channel_embed = nn.Parameter(torch.randn(n_channels, q_dim) * 0.02)   # (C, D) 每个通道的路由身份向量
self.group_proto    = nn.Parameter(torch.randn(n_groups, q_dim) * 0.02)   # (G, D) 每组的原型向量

# forward 中，分组切片替换为软加权
route_logits  = self.channel_embed @ self.group_proto.T          # (C, G)
route_weights = torch.softmax(route_logits, dim=1)               # (C, G)，每个通道对 G 组的归属权重

for g in range(G):
    w_g = route_weights[:, g].view(1, C, 1)                       # (1, C, 1)
    emb_g = emb * w_g                                              # 软门控：每个通道按权重贡献给这一组
    # 其余仍是该组独立 query + 独立 MultiheadAttention，attends over 全部 C 个通道（而非硬子集）
    ao, _ = self.mhca_groups[g](q_g, emb_g, emb_g, key_padding_mask=pad_mask)
```

**关键设计取舍**：软路由让每组的 query 依然能看到全部 C 个通道（不像方案 A/现有 `grouped_q4` 那样硬性限制注意力窗口），只是通过权重 `route_weights[:, g]` 让每组"更关注"和自己相关的一批通道。这意味着**方案 B 不会像硬分组那样降低单组的注意力计算规模**（计算量接近 `multi_q`），但换来了：(a) 完全可微、无需处理离散路由的塌缩风险；(b) 分组边界随训练自动调整，不需要离线聚类。

### 3.2 训练稳定性风险与缓解

参考项目历史（R3 中 `soft_skip`、`multi_q` 等架构改动经常出现"某数据集大幅改善、另一数据集灾难性变差"的不稳定性），方案 B 的主要风险是**路由退化**：`route_weights` 训练后趋于均匀分布（每组都约等于 1/G），等价于退化回 `full`，分组形同虚设。

缓解措施：
1. **熵正则化（可选，先不加，观察是否需要）**：如果观察到路由权重塌缩为均匀分布，再加一个鼓励"尖锐"分配的负熵损失项 `L_entropy = -mean(entropy(route_weights, dim=1))`，权重设为较小值（如 0.01），通过项目已有的 `aux_loss` 接口接入（`pipelines.py` 已经支持每个方法返回 `{forecast, impute, aux_loss}`，CRIB 的 KL 项、CoIFNet 的重建项都是走这条路径，方案 B 复用即可，不需要改训练循环）。
2. **不做硬 top-1 路由 / Gumbel-softmax**：本轮先只验证软路由，不引入离散路由的负载均衡损失（`load_balance_loss`）——这是更激进的方案（记为方案 B'，见 §3.5 备选），本轮作为可选的第二阶段，视方案 B 软路由结果决定是否值得投入。
3. **收敛后可视化 `route_weights`**：训练结束后导出 (C, G) 权重矩阵，检查是否形成有意义的分组结构（比如某几个通道明显偏好某一组），作为"分组是否学到东西"的直接证据，而不只看最终 MSE。

| 文件 | 改动 |
|---|---|
| `src/models/misstsm.py` | `MissTSMLayer` 新增 `variant == "grouped_q_soft"` 分支：`channel_embed`、`group_proto` 参数 + 软门控前向逻辑（如上）；`forward` 返回值增加可选的 entropy 正则项（供 pipeline 取用） |
| `src/training/pipelines.py` | `MissTSMPipeline.forward` 在 `variant.startswith("grouped_q") and "soft" in variant` 时把 entropy 正则项接入 `aux_loss` |

### 3.4 变体命名

| 变体名 | 含义 |
|---|---|
| `grouped_q4_soft` | G=4，软路由，不加熵正则（主实验） |

### 3.5 备选：方案 B'（硬路由，暂不纳入本轮主实验）

若方案 B 软路由被观察到明显收益，可以再考虑 Gumbel-softmax 硬路由 + 负载均衡损失（类似 Switch Transformer 的 auxiliary loss `G · Σ_g frac_g²`）：这能真正降低单组计算量（每个通道只分给一个组，恢复 §1.1 提到的"缩小单查询信息面"的原始动机），但需要额外调负载均衡权重、退火温度等超参，训练不稳定风险更高。**本轮计划不包含方案 B'，留作方案 B 验证有效之后的下一步。**

### 3.6 实验矩阵

| 维度 | 取值 |
|---|---|
| 数据集 | Weather, Electricity, Traffic |
| 缺失类型 | random_point, continuous_segment |
| 缺失率 | 0.3, 0.5, 0.7 |
| 预测长度 | 96 |
| 种子 | 2024, 2025 |

**实验量**：1 变体（`grouped_q4_soft`） × 3 数据集 × 2 缺失类型 × 3 缺失率 × 2 种子 = **36 条**。
若观察到路由塌缩需要补跑 `grouped_q4_soft_ent`，再加 **36 条**（视 Phase 1 结果决定，不预先跑）。

### 3.7 判定标准

- **有效性**：`grouped_q4_soft` 相对 `full` 基线的改善幅度是否达到或超过方案 A（`grouped_q4_corr`）在同一数据集/条件下的改善——如果达到甚至超过，说明"训练时自动学习分组"至少不比"离线相关性聚类"差，且省去了聚类预处理步骤。
- **路由是否有意义**：导出训练后的 `route_weights` (C, G) 矩阵，计算每个通道的路由熵；若平均熵接近 `log(G)`（即均匀分布）则判定为"路由退化，未学到有效分组"，需要补跑熵正则版本。
- **稳定性**：跨 2 个种子的结果方差是否明显大于方案 A 和现有 `grouped_q4`——如果方差显著更大，说明训练时学习分组引入了额外的不稳定性，需要在结论中明确指出这一代价。

### 4.3 执行顺序

1. **Phase 0**：写 `scripts/precompute_group_order.py`，对 Weather/Electricity/Traffic 各跑一次相关性聚类，人工检查一下分组结果是否合理（比如 Weather 是否把温度类变量分到了同一组），确认没有明显 bug 再进入 Phase 1。
2. **Phase 1**：方案 A 和方案 B 可以并行跑（两者互不依赖），各 36 条，共 72 条。
3. 汇总对比四个变体（`full` / `grouped_q4` / `grouped_q4_corr` / `grouped_q4_soft`）在 3 数据集 × 6 条件下的 MSE，重点看 Traffic 是否被两个新方案救回来。
4. **Phase 2（按需）**：根据 Phase 1 结果决定是否需要熵正则消融或更细粒度分组，避免像本计划 §3.5 提到的方案 B' 那样过早引入高风险改动。

## 五、风险与注意事项

1. **方案 A 的相关性计算必须只用训练集统计量**，与项目现有约定（"标准化只用训练集统计量"，见 `docs/README.md`）保持一致，不能用验证/测试集数据算相关矩阵。
2. **方案 A 的排列结果要做一次人工合理性检查**：如果 Weather 聚类出来的分组和"温度/风速/辐射"这类物理直觉严重不符，需要先检查相关矩阵计算是否有 bug（比如是否不小心在归一化前用了含缺失值的序列），而不是直接归因于"聚类方法不好"。
3. **方案 B 训练时间会比 `grouped_q4` 略增**（多了两个小矩阵乘法算路由权重），预计增幅有限（<5%），但仍需要在结果表里像 R4 报告一样记录训练时间，避免只看 MSE 忽略成本。
4. **不要同时改多个变量**：方案 A、B 各自只改"分组来源"这一个变量，其余（q_dim、num_heads、组数 G=4、训练超参）保持和现有 `grouped_q4` 完全一致，确保对比是干净的单变量消融。
5. **异常种子单独标注**：延续 R1-R4 的一贯做法，若某个 (数据集, 缺失率, 缺失类型) 组合两个种子结果差异很大，在汇总表中单独标记，不直接吞进均值。

## 六、预期结论形式

本轮结束后，希望能回答：

1. `grouped_q4_corr`（方案 A）是否解决了 Traffic 上的不稳定问题？改善幅度多大？
2. `grouped_q4_soft`（方案 B）训练出的路由是否学到了有意义的分组结构（而非退化为均匀分布）？
3. 方案 A（离线聚类，零额外参数）与方案 B（端到端学习，增加路由参数）相比，谁的性价比更高——如果两者效果相近，优先推荐方案 A（更简单、更稳定、无需担心路由退化）。
4. Weather 上两个新方案是否都不劣于现有 `grouped_q4`，从而验证"Weather 优势来自巧合的列顺序"这一假设是否成立。
5. 是否值得进入方案 B' （硬路由 + 负载均衡损失）或更大组数 G 的下一轮实验。

结论将补充进《四轮实验综合总结报告.md》遗留问题 #5 的更新，或视规模独立成一份 `0709实验报告.md`。
