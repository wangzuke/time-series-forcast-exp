# 实验计划 0715：BiTGraph 与 HD-TTS 复现实验（高维高缺失率 MTS 预测基线构建）

> 承接：2024 年以来高维、高缺失率时间序列预测相关论文调研，以及对 BiTGraph（ICLR 2024）和 HD-TTS（ICML 2024）的重点筛选。
> 计划日期：2026-07-15
> 核心目标：复现并统一评估 **BiTGraph** 与 **HD-TTS** 在高维多变量时间序列、高缺失率（50% 以上）点缺失/块缺失条件下的预测性能，明确二者是否适合作为后续课题的核心基线与方法改进对象。

---

## 一、背景与目标

### 1.1 当前课题场景

当前课题已经收束到如下问题：

> **高维多变量时间序列在高缺失率，尤其 50% 以上点缺失/块缺失条件下，如何稳定预测，并且如何建模变量间依赖。**

本轮不再关注“变量整体缺失”（variable missing）作为主场景，因此 GinAR/IBN 类变量缺失工作暂不作为主复现对象。当前最值得优先复现的两篇工作是：

| 论文 | 会议 | 选择理由 |
|---|---|---|
| BiTGraph: Biased Temporal Convolution Graph Network for Time Series Forecasting with Missing Values | ICLR 2024 | 直接研究 missing values 下 MTS forecasting；覆盖 60%、80% 随机点缺失；核心机制是将 missing mask 注入 temporal convolution 与 graph convolution。 |
| HD-TTS: Graph-based Forecasting with Missing Data through Spatiotemporal Downsampling | ICML 2024 | 明确处理 temporal block / spatiotemporal block missing；适合高维传感器图；通过时间与空间多尺度表示补偿局部整块不可见。 |

### 1.2 官方代码确认

两篇论文均有官方开源代码。

| 工作 | 官方仓库 | 仓库状态与注意事项 |
|---|---|---|
| BiTGraph | `https://github.com/chenxiaodanhit/BiTGraph` | README 提供安装、数据下载、训练与测试命令；依赖较旧，`requirements.txt` 指定 `torch==1.8.0`；issue 中有人指出代码可能主要围绕 `seq_len=24, pred_len=24`，因此先按默认 24→24 忠实复现。 |
| HD-TTS | `https://github.com/marshka/hdtts` | README 明确是 ICML 2024 官方复现实验代码；提供 `conda_env.yml`、Hydra 配置和真实数据脚本；本计划只使用当前已经下载到 `dataset/` 的真实数据。 |

### 1.3 本轮实验目标

本轮实验面向“给后续方法研究建立可信 baseline”，不是立即追求改模型。

需要回答四个问题：

1. **能否跑通官方代码并复现论文趋势？**
   先确保两篇官方实现能在本地环境稳定运行，记录所有依赖和数据准备细节。

2. **在 50% 以上高缺失率下，BiTGraph 和 HD-TTS 谁更稳？**
   BiTGraph 原生适配随机点缺失；HD-TTS 原生适配块缺失。需要在统一协议下比较二者优势边界。

3. **高维变量依赖建模的差异是什么？**
   BiTGraph 通过 mask-biased graph convolution 动态调节图传播；HD-TTS 通过 spatiotemporal downsampling 学多尺度图表示。需要观察哪种更适合后续课题借鉴。

4. **后续课题应该基于哪条路线改进？**
   若点缺失下 BiTGraph 更强、块缺失下 HD-TTS 更强，则后续可以考虑 missing-pattern-aware 动态变量依赖 + 多尺度块缺失补偿的结合方向。

## 二、实验总览

### 2.1 实验阶段

| 阶段 | 内容 | 目标 |
|---|---|---|
| Phase 0 | 仓库克隆、环境搭建、数据准备 | 确保官方代码可运行，记录环境与数据路径 |

### 2.2 主评估对象

| 模型 | 主要数据集 | 主要缺失类型 | 重点关注 |
|---|---|---|---|
| BiTGraph | METR-LA, PEMS-BAY/PEMS, Electricity, ETTh1 | random point missing；后续扩展 block missing | 高缺失率点缺失下的 mask-biased temporal/graph modeling |
| HD-TTS | METR-LA, PEMS-BAY | block-t, block-st；必要时补 random point | 共同交通图数据上的时空多尺度补偿能力 |

## 六、Phase 3：统一高缺失率协议

### 6.1 设计原则

忠实复现只能说明“官方设定能跑”。为了服务课题，需要建立统一高缺失率协议：

1. 统一缺失率：50%、60%、70%、80%。
2. 统一缺失类型：random point missing、temporal block missing、spatiotemporal block missing（若数据有图结构）。
3. 统一记录实际缺失率，而不是只记录生成参数。
4. 优先在共同数据集上比较：METR-LA、PEMS-BAY/PEMS。

### 6.2 实验矩阵

| 数据集 | 变量数 | 模型 | 缺失类型 | 目标缺失率 |
|---|---:|---|---|---|
| METR-LA | 207 | BiTGraph, HD-TTS | random point | 0.5, 0.6, 0.7, 0.8 |
| PEMS-BAY/PEMS | 325 | BiTGraph, HD-TTS | random point | 0.5, 0.6, 0.7, 0.8 |
| METR-LA | 207 | BiTGraph, HD-TTS | temporal block | 0.5, 0.6, 0.7, 0.8 |
| PEMS-BAY/PEMS | 325 | BiTGraph, HD-TTS | temporal block | 0.5, 0.6, 0.7, 0.8 |

### 6.3 BiTGraph 扩展 block missing

BiTGraph 原代码 `data/GenerateDataset.py` 中 `get_0_1_array` 只实现随机点缺失。需要新增 block mask 生成函数。

建议新增函数：

```python
def get_point_mask(shape, rate, seed=None):
    ...

def get_temporal_block_mask(shape, rate, block_len=12, seed=None):
    """
    shape: [T, N, 1]
    随机选择时间起点，将连续 block_len 个时间步的所有变量置为缺失，
    重复直到实际缺失率接近目标 rate。
    """
    ...

def get_spatiotemporal_block_mask(shape, rate, block_len=12, node_frac=0.2, seed=None):
    """
    随机选择时间段和节点子集，形成时空块缺失。
    """
    ...
```

新增 CLI 参数：

```bash
--missing_type random_point | temporal_block | spatiotemporal_block
--block_len 12
--node_frac 0.2
--mask_seed 2024
```

注意事项：

- 改动前先复制一份官方原始仓库 commit hash，记录在 `repro_notes.md`。
- 新增缺失类型时不要改变原 `random_point` 结果，保证忠实复现仍可运行。
- 每次生成 mask 后打印并保存实际缺失率。

### 6.4 HD-TTS 统一缺失率扩展

HD-TTS 的缺失由 Hydra 配置控制，例如：

- `dataset=la dataset/mode=block_t`
- `dataset=la dataset/mode=block_st`
- `dataset=bay dataset/mode=block_t`
- `dataset=bay dataset/mode=block_st`

若要构造 50/60/70/80% 的统一缺失率，可新增配置：

```text
config/dataset/mode/high_point_50.yaml
config/dataset/mode/high_block_t_50.yaml
config/dataset/mode/high_block_st_50.yaml
...
```

或直接用命令行覆盖：

```bash
python experiments/run_realworld.py \
  model=hd_tts_amp \
  dataset=la \
  dataset/mode=block_t \
  dataset.mode.p_fault=0.02 \
  dataset.mode.min_seq=12 \
  dataset.mode.max_seq=48
```

执行原则：

- 每组参数必须先跑一个 mask-only 检查脚本，计算实际 missing ratio。
- 若生成参数与实际缺失率不线性对应，使用二分或网格搜索找到接近 0.5/0.6/0.7/0.8 的参数。
- 最终实验表以“实际缺失率”为准。

### 6.5 统一协议验收

| 问题 | 判定方式 |
|---|---|
| 点缺失高缺失率谁更强 | 比较 METR-LA / PEMS-BAY 上 50%-80% random point 的 MAE/RMSE |
| 块缺失高缺失率谁更强 | 比较 METR-LA / PEMS-BAY 上 temporal block 的 MAE/RMSE |
| HD-TTS 多尺度是否必要 | 比较 `hd_tts_amp` 与 `tts_amp`/`tts_imp` |
| BiTGraph mask bias 是否必要 | 如时间允许，关闭 Biased GCN bias 或使用普通填 0 baseline 做消融 |
| 高维下效率是否可接受 | 记录峰值显存与单 epoch 时间，尤其关注 PEMS-BAY |

## 八、执行顺序建议

### 8.1 最短可行路径

如果算力或时间有限，按以下顺序执行：

1. BiTGraph：Metr-LA，`mask_ratio=0.6, 0.8`，`seq_len=24, pred_len=24`。
2. HD-TTS：METR-LA 的 `block_t, block_st`。
3. 对齐 METR-LA：BiTGraph 扩展 temporal block，与 HD-TTS 比较。
4. 补 PEMS-BAY/PEMS。

### 8.2 标准执行路径

| 顺序 | 内容 |
|---|---|

## 九、风险与应对

### 9.1 BiTGraph 风险

| 风险 | 应对 |
|---|---|
| 旧版 PyTorch 安装困难 | 先 CPU smoke test；必要时升级 PyTorch 并记录所有兼容性改动 |
| 代码可能只适配 24→24 | 忠实复现阶段只用 24→24；扩展窗口长度另开分支，不混入本轮主结果 |
| README 数据链接失效 | 本轮已下载数据优先使用本地 `dataset/`；记录来源和 checksum |
| 只支持随机点缺失 | 新增 block mask 函数，但保持原 random point 逻辑不变 |
| issue 中存在实现疑问 | 记录疑问，不擅自“修正论文实现”；需要修改时保留 patch diff |

### 9.2 HD-TTS 风险

| 风险 | 应对 |
|---|---|
| PyG 依赖安装失败 | 固定 PyTorch/CUDA/PyG 三者版本，记录最终安装命令 |
| 本地文件路径与 HD-TTS 默认缓存不一致 | 优先通过软链接或最小数据加载 patch 指向本地 `dataset/` |
| PEMS-BAY 训练开销大 | 先用 `epochs=2 train_batches=5` 验证，再跑完整实验 |
| 缺失率参数与实际缺失率不一致 | 先写 mask 统计脚本，以实际缺失率入表 |
| HD-TTS 与 BiTGraph 输入窗口/预测窗口不同 | 忠实复现与统一协议分开记录，不混淆结论 |

### 9.3 结论风险

本轮不能只给“谁 MAE 更低”的结论，需要区分：

- 点缺失 vs 块缺失；
- 忠实复现 vs 统一协议；
- 官方数据集 vs 我们构造的高缺失率设定；
- 性能优势 vs 训练成本。

如果某个模型在一个条件下失败，不直接判定模型无效，而要说明失败原因：环境、数据、缺失生成、实现限制或方法本身不适配。

## 十一、预期结论形式

本轮实验结束后，理想情况下应形成如下判断：

1. **若 BiTGraph 在点缺失 60%/80% 下稳定优于 HD-TTS**：后续点缺失主基线采用 BiTGraph，并围绕 mask-conditioned variable dependency 做改进。
2. **若 HD-TTS 在 block-t/block-st 下明显优于 BiTGraph**：后续块缺失主基线采用 HD-TTS，并围绕多尺度缺失补偿做改进。
3. **若二者各有优势**：后续方法方向可以定义为“BiTGraph 式 mask-aware 动态变量依赖 + HD-TTS 式多尺度时空补偿”的结合。
4. **若复现差异较大**：先完成复现报告，不急于做方法改进；必须把差异原因查清楚。

这份计划的定位是复现与基线建设。只有当 Phase 2 和 Phase 3 的结果稳定后，才进入下一步方法设计。
