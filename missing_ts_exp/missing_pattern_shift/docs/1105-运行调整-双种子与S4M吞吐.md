# 运行调整：双种子与 S4M 吞吐核验

日期：2026-11-05。

## 主配置修订

用户将主分析训练重复从 5 个种子减为预先固定的 `2024, 2025`。随后又将固定测试掩码从 5 份减为 `9101, 9102` 两份；修订主清单为 144 个训练运行、720 个测试评测。此前 `2026--2028` 的 JSON、检查点和日志，以及已生成的其余测试掩码 JSON，均保留为归档探索结果，不进入修订主统计。

## S4M batch-size 烟测

在 Weather、H=24、B=24、相同数量级训练窗口下，使用作者 S4M 网络，结果如下。该烟测只用于资源选择，不进入主指标表。

| batch size | 计时（秒） | 峰值已分配显存（GiB） | 结论 |
|---:|---:|---:|---|
| 32 | 14.89 | 3.19 | 最快，采用 |
| 64 | 17.53 | 6.29 | 吞吐下降 |
| 96 | 24.62 | 9.41 | 吞吐进一步下降 |

因此 24GB RTX 3090 的未用显存不是应增加 batch 的充分理由；S4M 在此输入长度和模型配置下的最优候选是 `batch_size=32`。

## 官方 CUDA kernel

原始 S4M 日志显示其 structured Cauchy/Vandermonde kernel 未被加载，退回 Python 慢实现。已使用作者仓库自带的 `extensions/kernels/setup.py` 和本机 CUDA 11.8 工具链构建 `structured_kernels`，并修正实验适配层的官方 S4 子包路径。导入核验给出 `has_cuda_extension=True`；修复后的同一 smoke 不再出现 fallback 警告，计时为 14.92 秒。该变更不替换模型结构或训练协议，只启用作者实现提供的可选加速后端。
