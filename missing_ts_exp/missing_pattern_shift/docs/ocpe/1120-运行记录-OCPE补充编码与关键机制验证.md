## 2. 数据与掩码控制

Weather保留原始CSV、行顺序、变量顺序和切分；训练段81个`-9999`标记为无效，统计量只由有效训练值估计。无效历史不参与观测似然，无效未来标签不参与损失和指标。没有用插值后的标签充当真实监督。

| 对象 | 实施情况 |
|---|---|
| P训练 | 保留原种子派生规则，随epoch更新；新增模型不改变掩码 |
| P验证/测试 | 保留原固定规则，兼容此前OCPE测试掩码 |
| B_u训练 | 新增带epoch的新版本规则，所有版本共享 |
| B_u测试 | 保留旧`B-uniform-v1`测试规则与采样顺序 |
| 跨模型一致性 | 协议中保存人工/有效掩码样例指纹；训练逐epoch与测试全窗口记录实际有效掩码序列哈希，汇总自动核对 |

实际序列哈希同时包含窗口索引和打包后的有效掩码，可在相同训练顺序下跨版本核对；样例指纹与完整测试序列哈希分别标注，不混为一项。

旧1113统一框架的B、上一轮OCPE的集中位置B与本轮B_u不同。历史数字不直接并入本轮模型排名。

## 3. 已完成的预检

- 新编码各模式与冻结旧高斯实现的对应公式一致；CPU/GPU FP32最大绝对差约`2.53e-7`。
- 三数据集、两种测试家族、两个测试种子，共12组历史掩码样例指纹兼容核对通过。
- P训练掩码规则兼容；P/B_u训练随epoch更新，测试固定。
- Weather数据质量、自然无效值屏蔽和有效训练统计量检查通过。
- 四版本共同模块初始化一致，新增零投影使初始预测与F0相同；额外前端初始化保持CUDA随机状态，避免意外改变共同dropout随机流。
- 编码投影更新后，预测梯度可以到达载荷和残差方差参数。
- 四版本都实际调用官方S4 CUDA Cauchy运算，未静默使用慢速替代路径。
- 检查点状态回填与短训练/测试流程通过；短运行包含microbatch32、有效batch64的累积路径。

正式启动的代码指纹与最终预检记录一致。详见[预检JSON](../../exp/diagnostics/ocpe_fusion_uniform_r50_l96_h96_1120/correctness.json)。

## 4. GPU与吞吐安排

用户本轮授权使用空闲显卡。启动检查发现GPU0、1、7空闲，GPU5已有其他用户高负载任务，因此本轮选择0、1、7。

以Electricity/F3、batch64、每任务6个加载worker进行同步起跑的端到端短测：

| 同卡并发任务数 | 整卡合计样本/秒 |
|---:|---:|
| 1 | 806.6 |
| 2 | 1386.5 |
| 3 | 1980.1 |

采用测试范围内总吞吐最高的每卡3任务，共9个并行槽位；其余任务自动排队。测试中每进程PyTorch峰值reserved约300MiB，此数不包含全部CUDA上下文开销；调度器仍按每任务5000MiB预约并保留额外余量。

正式配置：microbatch64、有效batch64、workers6、计算线程2；优化器/训练轮数与计划一致。workers从计划中的单任务起点10调整为6，是为控制9任务并发时的CPU加载压力，不改变掩码或有效batch。

并行短测不能保证长时间训练始终保持同样吞吐。调度器持续记录GPU显存和利用率；检测到其他进程占用目标卡时暂停在该卡启动新任务。任务失败或掩码不一致时停止新增调度并写入失败状态，已在运行的独立任务保留。

详见[并行短测记录](../../exp/diagnostics/ocpe_fusion_uniform_r50_l96_h96_1120/parallel/summary.json)。
