## 1. 研究范围与固定配置

| 项目 | 设置 |
|---|---|
| 数据集 | 本地 `weather.csv`，21 个变量；训练窗口数 36,696 |
| 版本 | LI-S4、STAT-S4、PU-S4 |
| 输入 / 预测长度 | 96 / 96 |
| 历史输入缺失 | 每窗口、每变量精确 50%；未来目标完整 |
| P / B | 原逐变量散点缺失 / 两个分离的 24 步块缺失 |
| 训练模式 | P、B，各自独立训练 |
| 训练种子 | 2024、2025 |
| 测试条件 | P、B、B-uniform；每种使用掩码种子 9101、9102 |
| 切分与标准化 | 复用原协议的时间顺序 70%/10%/20% 划分；训练段统计标准化 |
| 主干 | 普通 DPLR S4，2 层、宽度 64、状态维度 32、前馈宽度 128、dropout=0.1 |
| 后验前端 | 静态窗口潜变量秩 16；相同载荷和噪声参数化 |
| 训练损失 | 未来标准化 MSE；STAT/PU 加同一观测似然，权重 0.1 |
| 优化器 | AdamW，基础学习率 1e-3；普通参数 weight decay=1e-4，SSM 特殊组沿原规则 |
| 训练控制 | 最多 30 epoch，patience=5，同模式验证 MSE 选择检查点；梯度裁剪 1.0 |
| batch / 精度 | microbatch=有效 batch=64，不累积；FP32 与所需 complex64 |
| 数据加载 | workers=10，主进程计算线程数 2 |

**新增 12 次训练：3 版本 × 2 训练模式 × 2 训练种子。** 每个检查点评估六个测试条件，合计 72 项评估，其中主 P/B 为 48 项，B-uniform 为 24 项。独立保存的短训练 smoke 不进入结果。

Weather 的三个模型参数量分别为：LI-S4 **80,373**，STAT-S4 与 PU-S4 均为 **112,031**。训练目标、输入信息边界和报告口径均与原实验相同。

原模型 `posterior_s4.py`、原训练入口 `run_posterior_s4.py`、公共数据协议及其依赖的核心源码指纹均保持不变，原 Electricity/ETTh1 结果不覆盖、不重训。

调度、只读报告和分析工具增加了按 suite 和数据集汇总的支持；这些更改不改变模型训练。Weather 的来源记录同时包含原训练入口和新增适配文件的哈希。

## 4. GPU 与队列

使用用户此前指定的 GPU 0/5，每卡最多三个正式训练进程。启动核验时，GPU 0 空闲，GPU 5 上已有其他高负载进程，因此首批三个 P/2024 条件在 GPU 0 并行运行。

调度器检查实际 GPU 计算进程：发现不属于本套件的进程时，不往该卡新增任务。GPU 5 空闲后才会自动加入；不会停止、迁移或抢占其他进程。每个候选启动还检查可用显存和预留量。

首批六个种子 2024 条件完成训练与评估后，补齐种子 2025 的六个条件。发生程序或数值错误会停止新增任务调度，保存错误记录，已在运行的独立条件继续保存自身结果。

## 6. 完成结果摘要

表中为标准化 MSE，先在每个检查点内平均两个测试掩码，再平均两个训练种子。PU-S4 是完整方法，现命名为 OCPE-S4；历史实验 ID 保留 PU-S4，避免更改可追溯记录。

| 版本 | P→P | P→B | B→P | B→B |
|---|---:|---:|---:|---:|
| LI-S4 | 0.182536 | 0.254635 | 0.213743 | 0.171449 |
| STAT-S4 | 0.196678 | 0.201936 | 0.220535 | 0.179801 |
| OCPE-S4（PU-S4） | 0.184587 | 0.186052 | 0.190103 | 0.173468 |

相对 LI-S4，完整方法在 P→B、B→P 的 MSE 分别降低 26.9%、11.1%，两个训练种子方向一致；P→P、B→B 的均值分别增加 1.1%、1.2%。相对同参数量的 STAT-S4，完整方法四格均值均改善，两种错配分别降低 7.9%、13.8%。

Weather 因此提供了比 Electricity 更接近“改善错配且基本保持匹配精度”的证据；但仍只有两个训练种子，不将小幅差异描述为统计显著，也不据此忽略 ETTh1 的负结果。

完整性核验及逐种子分析已自动写入该套件 `summary/.../analysis/`，包含 12 个任务、72 项测试和 24 个检查点的审计记录。
