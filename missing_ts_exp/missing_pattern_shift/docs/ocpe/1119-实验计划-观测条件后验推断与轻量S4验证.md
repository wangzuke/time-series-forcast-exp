# 实验计划：观测条件后验推断能否改善 P↔B 缺失模式错配？

**日期：2026-11-19**  
**状态：首轮两数据集的 24 次训练、144 项测试，以及后续 Weather 的 12 次训练、72 项测试均已完成。当前结果与结论见[OCPE-S4 三数据集报告](1120-实验结果-OCPE-S4-三数据集-r50-2x2矩阵.md)；[早期运行记录](archive/1119-运行记录-后验推断与轻量S4.md)已归档。本文保留原预设协议。**  
**第一阶段 backbone：普通 S4，采用小规模配置，不包含 S4M 的原型检索。**

**精简修订：首轮只保留 3 个训练版本，核心真实数据训练从 48 次减至 24 次；独立线性模型和逐组件消融暂缓。**

## 阅读摘要

本轮要检验一个具体想法：**面对不同排列方式的缺失，先根据实际可见观测推断同一个潜在表示，并计算该表示的不确定性，再交给预测网络，是否比直接把填充值和掩码交给网络更可靠？**

这里的“推断”有明确的线性高斯模型和可计算公式，不把概念描述当作已经成立的方法。与此同时，概率模型有理论基础，也不代表它一定适合真实时间序列，或一定能改善 P↔B 错配。本计划分别检验计算正确性、实际效果和效果来源。

| 审查重点 | 本计划的选择 |
|---|---|
| 方法是什么 | 一个可训练的观测条件后验前端，输出潜在表示及不确定性；后接轻量 S4 和预测头 |
| 为什么先用普通 S4 | 保留通用时序建模能力，并减少原型库、检索、掩码双流等组件对归因的干扰 |
| 怎样判断方法是否有效 | 与插值加掩码的普通 S4 比较整体收益，再与参数量和辅助损失相同的统计特征 S4 比较后验表示的作用 |
| 数据范围 | Electricity 为首轮重点，ETTh1 为核心复核；Weather 为后续扩展，暂不加入 Traffic |
| 核心规模 | 3 个版本 × 2 个数据集 × 2 种训练模式 × 2 个训练种子，共 24 次真实数据训练 |
| 如何控制成本 | 先做正确性检查和 GPU 性能检查，再做 Electricity 单种子试验，最后补齐核心矩阵 |
| GPU 重点 | 确认实际调用官方 S4 CUDA kernel；后验在 GPU 上批量计算；实测数据加载、batch 和求解开销 |
| 实施边界 | 按冻结配置运行三个版本；不根据首批测试分数自动调整方法，不提前承诺效果或论文创新性 |

正文说明实验决策，附录 A 给出可直接指导实现的公式，附录 B 列出代码和文档依据。

## 1. 研究问题与可被否定的假设

### 1.1 固定问题场景

训练输入只有一种缺失模式：散点缺失 P，或连续块缺失 B。部署时输入缺失模式可能改变。训练和测试的缺失率、历史长度、预测长度、变量集合保持一致；未来预测目标完整。

我们检验的是**缺失位置分布发生变化时的预测能力**。当前使用与数值独立生成的人工掩码，属于受控的、可忽略缺失机制；不把结论推广到“数值越异常越容易缺失”的 MNAR 场景，也不宣称这些按窗口生成的掩码已经还原真实设备故障过程。

### 1.2 三个主要假设

| 假设 | 直观含义 | 主要证据 |
|---|---|---|
| H1：整体方法有收益 | 使用后验前端，比常规缺失输入处理获得更好的预测 | PU-S4 对比 LI-S4 |
| H2：后验表示有贡献 | 同样具有可学习观测模型和辅助训练，后验表示优于当前统计特征表示 | PU-S4 对比 STAT-S4 |
| H3：收益与错配问题有关 | 改善不只是所有条件下相似幅度的普通精度提升 | 同时比较匹配误差、错配误差及固定测试条件下的错配代价 |

H1、H2、H3 可以分别成立或不成立。例如只优于普通 S4、没有优于 STAT-S4，只支持整体方案有收益，不能将收益归因于后验表示。首轮将后验均值与方差视为一个完整前端，不单独检验或宣称方差输入的增量贡献。所有实验保留负结果。

## 2. 第一版方法：明确做到哪一步

### 2.1 结构与信息流

```text
当前样本的历史观测值 X_obs、掩码 M
                    │
          可学习的线性高斯观测模型
                    │
      对每个历史前缀计算潜变量的后验
                    │
       后验均值 m_t、后验方差 diag(Σ_t)
                    │
         特征投影 → 2 层 S4 → 预测头
                    │
                未来 96 步预测
```

前端设定：一个长度为 96 的历史窗口由一个低维潜变量 `z` 描述，不同时间和变量通过不同的载荷与 `z` 联系。看到哪些位置，就使用哪些位置的观测更新 `z`。具体公式见附录 A。

对于第 `t` 个前缀，输出的是**同一个窗口潜变量 z 在前 t 步观测条件下的估计**，不是具有独立转移方程的动态状态 `z_t`。S4 再处理这些逐前缀更新的表示。所有前缀均位于预测起点之前。

普通 S4 的内部递归状态与这里的概率后验是两个对象。不能以“S4 属于状态空间模型”为由，认为它已经完成了这个前端的计算。

### 2.2 首版需要遵守的理论边界

1. 在线性高斯模型正确、参数已知且缺失机制可忽略时，后验公式成立；如果未来也由同一潜变量线性生成，后验均值的线性读出是平方损失下的最优预测。
2. 真实数据上的载荷和噪声需要学习，模型也可能设定错误。因此精确计算的是**所设模型下的后验**，不是已经证明符合真实数据生成机制的后验。
3. 接入非线性 S4 后，第一条的预测最优性结论不直接适用于整网。
4. 静态潜变量模型中，缺口内没有新观测时，后验保持不变；其方差不会因为时间流逝自动增大。首版不声称解决动态状态的过程噪声累积问题。
5. 线性高斯条件推断和概率时序建模均有既有研究。本轮首先检验它们在当前 P↔B 框架中的适用性，不把标准后验公式、拼接方差或换用 S4 单独写成已确认的新颖贡献。

## 3. 数据、掩码与公平比较

### 3.1 核心协议

| 项目 | 固定设置 |
|---|---|
| 核心数据集 | Electricity：321 变量；ETTh1：7 变量 |
| 后续扩展 | Weather：21 变量；不默认加入核心队列 |
| 历史 / 预测长度 | L=96，H=96 |
| 输入缺失率 | 每个窗口、每个变量精确缺失 48 个位置 |
| P | 每变量等概率选择 48 个缺失位置；允许随机形成短连续段 |
| B | 每变量两个 24 步缺失块，块间至少保留一个观测位置 |
| 通道间关系 | 各变量独立抽样缺失位置；本轮不改变跨变量同步程度 |
| 训练种子 | 2024、2025 |
| 验证掩码 | 与训练模式相同；固定种子为训练种子 + 10000 |
| 测试掩码种子 | 9101、9102 |
| 训练掩码 | 按 epoch 更新；同数据集、训练模式、训练种子、epoch、窗口索引的掩码跨模型完全相同 |
| 预测目标 | 完整；前端和预测器均不能读取未来目标作为输入 |

切分和标准化复用 `exp/scripts/protocol.py`：ETTh1 使用既定 12/4/4 月划分；Electricity 使用 70%/10%/20% 时间划分。标准化统计只从训练段计算。验证、测试可使用切分边界之前的历史上下文，但预测目标必须落在对应时间段。

模型训练只使用人工缺失后的历史观测，以及合法的完整未来预测标签。**不利用被人工隐藏的历史真值进行前端预训练、插补监督或载荷初始化。** 隐藏历史真值仅可由隔离的评价流程用于诊断。训练集均值和标准差沿用既有框架从完整训练段估计，这是本受控实验的共同预处理约定，不扩大为“训练时也没有任何完整数据”的设定。

### 3.2 旧结果的使用边界

现有部分 B24 结果使用过允许两块相接的旧采样器，可能产生 48 步缺口。本轮所有新模型固定采用当前 `per_channel_block_mask` 的严格分离实现，记录源文件哈希和掩码指纹。

旧报告只用于动机和背景。与 S4M 等已有模型作数值比较时，只有数据、切分、掩码和指标均核对一致的严格协议结果才可并列；不把旧 B 结果直接作为本轮方法的优劣依据。本轮不复用 S4M 权重初始化普通 S4。

### 3.3 除了缺失数量，还要审计缺失位置

当前 B 采样器用多项分布分配块外和块间的观测间隔，满足严格分离，但**不等价于所有合法块位置组合等概率**。因此必须报告：逐时间位置缺失概率、距预测起点最近的观测位置、最长缺失段、每变量缺失数量，以及通道间掩码重合程度。

为避免效果只适用于这一位置偏好，核心训练完成后，对同一批 checkpoint 增加一个无需重训的 `B-uniform` 测试：在所有满足“两个 24 步块、块间至少一个观测”的合法位置组合中等概率采样，仍使用两个固定测试种子。它单列为块位置分布改变的压力测试，不与主 B 测试混合，也不把 B 训练→B-uniform 误写成完全匹配条件。

## 4. 三个核心版本：只保留两个关键对比

全部 S4 版本采用相同的 S4 主干、预测头、训练规则和数据。区别限于前端。所有版本都能利用缺失位置；基础版本不能只看填补值而看不到掩码。

| 编号 | 版本 | 前端 / 读出 | 作用 |
|---|---|---|---|
| V0 | LI-S4 | 历史内线性插值结果与 M 拼接，投影后送入 S4 | 常规缺失感知预测基线，回答“整体方法有没有收益” |
| V1 | STAT-S4 | 可学习观测模型的累计信息向量 b_t 与 log diag(J_t)，投影后送入 S4 | 与后验版本参数量和辅助损失一致，回答“后验表示有没有额外作用” |
| V2 | PU-S4 | 后验均值 m_t 与 log diag(Σ_t) 拼接，投影后送入 S4 | 完整候选方法 |

关键对比只有两组：**V2 对 V0 检验整体收益，V2 对 V1 检验后验表示的额外作用。** 保留 STAT-S4，是因为只有普通 S4 与完整方法两组时，无法排除新增参数、压缩表示和辅助损失带来的收益。

常规基线只保留插值加掩码，不再同时训练零填补版本。插值只使用当前历史窗口内的观测：内部缺口线性插值，边界缺口以最近观测延拓，不读取预测目标。掩码继续输入预测器，使其能区分观测值与插值值。

`J_t` 是后验精度矩阵，`b_t` 是观测信息的加权累计。STAT-S4 保留了可学习压缩、掩码相关统计及相同的观测似然训练，但不通过 `J_t m_t=b_t` 的解来构造预测特征。它不是一个完全保留完整矩阵信息的等价表示；因此该比较检验的是两种具体前端的归纳偏置，不宣称隔离了所有可能的统计表示。

STAT-S4 的辅助似然仍需要末步求解。这里的“不使用后验”专指预测特征路径，而不是声称其训练完全没有矩阵求解。V1/V2 的观测模型、特征维数、S4 和预测头完全相同，构成主要的参数量控制。

V0 与候选方法的前端参数量可能不同，结果必须同时列出各组件参数量。不能仅凭 V2 胜过 V0，就把收益归因于后验机制。不确定性单独消融和独立线性预测模型都移出首轮，等完整方法显示收益后再决定是否补充。

所有版本第一轮均不增加原始观测旁路、原型检索、额外掩码增强或目标模式训练。若需要这些改动，应作为后续的新版本记录。

## 5. 实验顺序与规模

### 阶段 A：先确认计算正确，再讨论效果

**数值和接口检查，无需真实数据完整训练：**

- 在小维度样例上，用 CPU float64 的直接可见子矩阵计算，核对 GPU 批量计算的后验均值、协方差和边缘似然；float64 参考相对误差目标为 1e-6，FP32 实现目标为 1e-4，近零项另用绝对误差判定。
- 检查全观测、无观测、前缀无观测等边界；无观测时返回先验均值 0、协方差 I，不能出现 NaN。
- 固定 M，任意改变缺失位置的底层数值，输出必须保持不变；检查梯度可达载荷、噪声参数及 S4。
- 对相同模型参数，新增观测后后验协方差应按半正定顺序不增。该性质不用于比较数量相同但位置不同的 P/B 掩码。
- 核对输出为 `[batch, 96, C]`，预测对有效观测扰动有响应，checkpoint 保存恢复前后一致。

这些是对核心数学运算、信息边界和模型接口的必要验证，不以大量重复单元测试代替真实实验。

**可控合成核对：不新增训练版本。**

生成独立窗口：`z ~ N(0,I)`，历史和未来均由同一个 z 线性生成，再加独立高斯噪声。载荷随时间变化，避免因载荷与时间无关而使等数量 P/B 的最终精度矩阵必然相同。历史和未来载荷采用平滑时间基函数与通道系数组合；生成参数在实验清单中固定并保存。

| 项目 | 设置 |
|---|---|
| L / H / C / 潜变量秩 | 96 / 96 / 12 / 8 |
| 核对样本 | 每个生成重复 2048 个独立窗口；不划分训练集、不拟合模型 |
| 历史 / 未来噪声标准差 | 0.2 / 0.1；保存实际载荷和尺度，不用测试统计重标定 |
| 数据生成重复 | 7201、7202、7203 |
| 缺失模式与掩码种子 | P、B；9101、9102 |
| 核对对象 | 用真实生成参数计算后验、条件均值和条件方差 |
| 拟合次数 | 0；首轮取消两个额外线性版本的训练 |

另计算使用**真实生成参数**的 oracle 条件均值及其理论条件风险，无需训练。它用于核对实现与模型设定下的预期行为，不能拿已知真参数的优势证明可学习方法优于其他模型。

报告后验数值误差、oracle 的潜在状态估计误差、未来 MSE 与理论条件风险的吻合程度，并核对 90% 边际预测区间覆盖率。这里只验证公式与实现，不验证可学习方法是否能逼近 oracle。学习观测模型的可靠性留在真实数据诊断中评价，核心三个版本只输出未来点预测，不宣称已建模未来预测区间。

### 阶段 B：GPU 正确性与吞吐检查

用真实数据的一小段训练数据完成第 8 节的性能检查和短训练。只使用训练段与同模式验证段，不读取测试分数。

通过条件包括：实际加载并调用 S4 CUDA kernel、前后向有限、前端梯度正常、动态掩码生效、无逐样本 CPU 求解瓶颈，并形成整网耗时与显存记录。未通过时先修复实现，不扩大训练规模。

### 阶段 C：Electricity 单种子可行性试验

3 版本 × P/B 两种训练模式 × 种子 2024，共 **6 次训练、24 项主测试评估**。每个训练检查点评估 P/B × 两个测试掩码种子。

本阶段用于确认真实数据上有无初步收益，以及 S4 是否有效学习输入。单种子不能作为稳定结论。如果发现数值故障、输入响应塌缩或训练未收敛，先处理这些问题，不能将故障解释成鲁棒性，也不能据此判定统计方法已经被否定。

若实现可靠但没有收益，应如实形成负结果和诊断，决定是否需要修改方法。**一旦查看测试结果后修改结构或超参数，原试验即归为探索结果，不能再把同一测试集上的后续改善称为未参与开发的独立确认。**

### 阶段 D：补齐核心矩阵

在配置冻结且没有因测试结果修改方法的前提下，补齐 Electricity、ETTh1 的两个训练种子：

| 范围 | 训练数 | 主 P/B 测试数 |
|---|---:|---:|
| Electricity，3 版本 × 2 模式 × 2 种子 | 12 | 48 |
| ETTh1，3 版本 × 2 模式 × 2 种子 | 12 | 48 |
| **核心真实数据合计** | **24** | **96** |

阶段 C 的 6 次训练只有在协议和训练配置完全一致时才能计入上述 24 次，否则单列归档。因此通常为补充 18 次训练，而非再完整训练 24 次。

核心 24 个检查点另在 B-uniform 的两个测试掩码上评估，共 **48 项附加评估**。主 P/B 与附加测试合计 144 项，不代表 144 次训练。

### 后续扩展：不自动纳入首轮队列

- **Weather 复核：补充执行已完成。**三个版本的完整矩阵增加 12 次训练、72 项测试，独立保存；配置和运行入口见 [Weather 补充实验记录（归档）](archive/1119-补充实验-Weather后验推断与轻量S4.md)。
- **机制细分：**完整方法有效后，再按结果决定是否增加“仅后验均值”、取消辅助损失或独立线性读出；本轮不预先实现或排队这些版本。
- **S4M 接入与更多训练种子：**核心证据支持后再设计。两种训练种子不足以支撑强显著性或跨数据集普遍有效的结论。

这些扩展在新的实验清单中登记，不能因为计划中提及就默认全部启动。

## 6. 统一模型和训练配置

| 项目 | 第一版固定设置 |
|---|---|
| S4 实现 | 现有 S4M 仓库捆绑的普通 `S4Block`，明确使用 DPLR 模式；记录实际源码哈希 |
| S4 层数 / 宽度 / 状态维度 | 2 / 64 / 32 |
| S4 block 外部结构 | 残差、LayerNorm、宽度 128 的前馈层；dropout=0.1 |
| 真实数据潜变量维度 | r=16；合成数据单独用生成秩 r=8 |
| 观测载荷 | 每个历史相对时间、每个变量有一个 r 维载荷，即 A 的形状为 `[96,C,r]` |
| 噪声 | 每变量一个可学习方差，时间共享；正值参数化，方差下限 0.01，初始化为 1 |
| 观测均值 | 每变量一个可学习均值，初始化为标准化空间的 0 |
| 载荷初始化 | 零均值小随机值，标准差 `0.1/sqrt(r)`；不用隐藏历史真值做 PCA 初始化 |
| 预测头 | S4 输出 `[B,L,64]`，共享时间线性映射 L→H，再共享通道线性映射 64→C |
| 主损失 | 标准化未来的平均 MSE |
| 观测辅助损失 | V1/V2 加上观测位置的归一化负对数边缘似然，权重 λ=0.1；V0 不含该观测模型 |
| 优化器 | AdamW，基础学习率 1e-3；普通参数 weight decay=1e-4 |
| S4 特殊参数组 | 遵循实现的 `_optim` 标记；SSM kernel 参数 weight decay=0，学习率不高于 1e-3；保存展开后的参数组 |
| 梯度裁剪 | 全局范数 1.0，记录裁剪前范数和触发频率 |
| 训练上限 / 早停 | 30 epoch / patience=5；按同训练模式验证集的未来 MSE 选择检查点 |
| 初始有效 batch | 64；由性能检查确定 microbatch 与必要的梯度累积，之后冻结 |
| 初始数值精度 | FP32；S4 的复数计算保持其需要的 complex64，后验求解至少 FP32 |

本轮是新模型的受控验证，不是复现完整 S4M，因此不直接沿用 S4M 的 SGD 或 512 宽度。已有 Adam 0.01 数值失败记录仍提示我们必须检查学习率与数值稳定性。

先固定以上配置，不默认进行大规模超参数搜索。若训练段/验证段检查暴露明确的数值问题，可以修订共同配置，但必须在主测试前记录理由和新版本；不能给候选方法额外的测试驱动调参机会。验证选择只使用未来预测 MSE，辅助似然单列记录，避免不同版本用不同目标选择最佳轮次。

同种子比较时，用独立随机数流控制主干初始化、前端初始化、DataLoader 顺序与掩码生成，尽可能使公共 S4/预测头初始权重及训练窗口顺序一致。不能让不同前端消耗的随机数数量间接改变数据顺序。

## 7. 评价方式：同时看预测质量和错配效应

### 7.1 主要指标与四格结果

**主指标为标准化 MSE，辅以标准化 MAE、原量纲 MSE/MAE。** 原量纲指标用于接续既有报告；标准化指标避免 Electricity 少数高量纲通道主导结论。不同数据集的原量纲 MSE 不直接平均。

每个版本完整呈现 P→P、P→B、B→P、B→B，并分别列出训练种子和测试掩码种子。先在每个训练种子内平均两个测试掩码，再总结两个训练种子的均值与范围。原始逐条件数值必须保留；不能将四次测试视为四次独立训练。

令 `E(A→B)` 表示 A 训练、B 测试下的误差。固定测试条件，分别计算：

- **B 测试的相对错配代价：**`E(P→B) / E(B→B) - 1`。
- **P 测试的相对错配代价：**`E(B→P) / E(P→P) - 1`。
- **最坏错配误差：**`max(E(P→B), E(B→P))`，只在同一数据集内比较。

同时直接报告候选方法相对各对照的两种错配误差改善，以及两种匹配误差的变化。不能用提高匹配误差来制造更小的错配代价；也不能仅比较 P→P 与 P→B 来隔离错配影响，因为测试输入本身同时改变。

### 7.2 机制诊断

| 诊断 | 做法 | 能支持的解释 |
|---|---|---|
| 输入使用情况 | 固定掩码扰动观测值；固定历史换 P/B 掩码，记录预测变化；比较训练均值预测参照 | 排查输出常量化或忽略输入；响应幅度本身不是鲁棒性评分 |
| 整体方法收益 | V2 对比 V0 | 完整前端是否优于常规插值加掩码输入 |
| 后验表示贡献 | V2 对比 V1，参数和辅助损失一致 | 后验表示是否优于当前统计特征表示；不单独归因于方差输入 |
| 不确定性可靠性 | 在预先固定、均匀抽取的至多 256 个测试窗口中，只对隐藏历史位置计算模型预测方差与误差、90% 边际覆盖率 | 检查观测模型的可信程度；不等于未来预测区间已校准 |
| 几何泛化 | 同一 checkpoint 增加 B-uniform 测试 | 是否依赖当前 B 采样器的位置分布 |
| 时间与通道差异 | 按未来步长、变量汇总误差，列出改善/退化通道比例 | 排查少数通道或短期预测主导平均收益 |

隐藏历史位置的预测方差必须用 `aᵀΣa + v_c` 计算，不能只用某个潜变量的方差代替。潜变量可发生旋转，不能把不同独立模型某一维的方差大小直接当成可比的物理量。

为控制存储，保留所有测试窗口的按窗口平均误差、按变量/步长汇总、固定诊断子集预测，不默认保存每个 checkpoint 的全部三维预测数组。

### 7.3 不确定性与统计报告

方法比较采用同一测试窗口和同一掩码的配对误差。由于窗口相互重叠，不能用逐窗口独立 t 检验制造很小的 p 值。

首轮以逐训练种子的方向、效应大小和跨掩码稳定性为主要证据。若补充区间，采用时间连续块的配对 bootstrap，块长至少 L+H=192 个窗口起点，并检查更长块的敏感性；明确其只描述固定训练模型下的测试时间抽样不确定性，不能代替训练重复的不确定性。若有效时间块太少，不报告看似精确的显著性结论。

## 8. GPU 高效执行方案

### 8.1 复用已有 S4 加速经验

已有吞吐记录表明，S4M 曾因 `structured_kernels` 未加载而退回慢路径；本地已构建官方扩展，并通过将捆绑的 S4 根目录加入导入路径解决。新适配器应复用这一环境和路径处理，不能另建一个没有扩展的环境后默认认为“已经在 GPU 上高效运行”。

开跑前记录并核验：

1. Python、PyTorch、CUDA、GPU 型号与 S4 源码版本。
2. `has_cuda_extension=True`，`structured_kernels` 的实际加载路径及导入失败原因（若有）。
3. DPLR kernel 配置为 CUDA 后端；通过一次 profiler 核对实际调用 Cauchy/Vandermonde 对应的 CUDA 路径。仅检查导入标志不够，因为 dtype、device、backend 也会决定分支。
4. 前后向 smoke 无慢实现 fallback；若不能启用已有加速路径，先处理环境，不静默开始完整队列。

普通 S4 模型中每层只注册实际执行的模块。现有 S4M 的 `S4_Layer` 注册了两份 S4 对象，但前向只调用其中一份；新轻量适配器不照搬这一未使用对象，避免冗余参数、优化器状态和参数量误报。

### 8.2 后验前端的 GPU 实现原则

- 输入、掩码、载荷、精度矩阵、求解结果全程驻留 GPU，不在前向中调用 NumPy、CPU 求解或逐窗口 `.cpu()`。
- 先按时间并行计算每步的信息增量，再沿历史维度 `cumsum`，得到所有前缀的 `J_t` 和 `b_t`。
- 对 `[batch,L,r,r]` 的精度矩阵做批量 Cholesky 求解；不用 Python 循环逐样本调用通用逆矩阵。
- 方差用 Cholesky 因子求得；观测似然复用末步分解结果。按矩阵恒等式只操作 r×r 矩阵，不构造 `(L×C)×(L×C)` 的稠密观测协方差。
- 避免显式展开 `[batch,L,C,r,r]` 巨型中间张量；采用矩阵收缩或按时间块计算等价的信息增量，并用 profiler 验证峰值内存。
- J 理论上含 I、应为正定。出现分解失败时记录条件数/尺度等诊断；只允许有记录、有上限的数值抖动处理，不能静默跳过样本或不断增大抖动掩盖问题。实际加过抖动的计算需与精确公式区分。

### 8.3 batch、数据加载和精度

已有 S4M smoke 中 batch=32 比 64/96 更快，但模型和前端已经改变，不能直接把旧最优值当作新模型结论。

性能检查使用 LI-S4、PU-S4 在 Electricity 的固定训练窗口和掩码：预热 20 个有效优化步，再计时 100 个有效优化步，重复 3 次；每个有效优化步包括累积所需的全部 microbatch。分别测量两种口径：预先放入 GPU 的批次用于测纯计算；真实 DataLoader 流程用于测端到端吞吐，后者包含等待加载、插值等预处理、搬运和优化更新。计时边界使用 CUDA 同步或 event，不在每个算子后同步。

分两步选取配置，避免组合爆炸：

1. 固定 microbatch=32，比较 `num_workers=0/4/10`，检查 CPU 数据准备与端到端吞吐。使用 `pin_memory=True`、异步数据搬运；线程数和预取参数写入记录。
2. 固定选定的数据加载设置，比较 microbatch=16/32/64，保持有效 batch=64，分别采用累积 4/2/1 次。记录等效优化步的耗时，不能用不同有效 batch 的 epoch 时间直接决定配置。

V0—V2 选择能兼容且整网效率合理的共同设置，之后冻结。若个别模型显存限制要求改变 microbatch，必须保持有效 batch 和损失归一化一致，准确记录；不能在失败后静默减半。训练、验证和测试均不丢弃尾部样本；训练最后一组不足 64 时，按实际样本数归一化梯度，不跨 epoch 拼组，并记录该组的实际有效 batch。

特别注意：`dynamic_epoch=True` 依赖 Dataset 的 epoch。默认不启用 `persistent_workers`；如启用，必须实现 worker 可见的 epoch 更新并核对掩码指纹，避免 worker 使用旧副本、各轮掩码实际不变。

首次正式配置使用 FP32，并对后验运算关闭可能影响求解精度的低精度/TF32 路径。AMP/BF16 只作为后续可选加速检查：前端分解和 S4 复数核保留所需精度，只有通过数值与短训练一致性检查才启用，且各版本规则一致。不为了提高表面利用率强行开启全网半精度。

### 8.4 资源调度和性能产物

用户已授权在 GPU 0/5 运行，启动前已核验两卡空闲。正式队列仅使用这两张卡，保护其他既有实验；不使用此前记录中的 GPU 4/7。

初始采用每张获分配 GPU 一个训练进程，独立训练条件可分配到多张卡；不默认采用 DDP，因为模型较小，通信可能增加成本。同卡并发只在实测整卡吞吐增加且显存有余量时采用。

性能报告至少包含端到端样本/秒、每 epoch 时间、训练总时间、推理延迟/吞吐、峰值 allocated/reserved 显存，并区分数据准备、后验前端、S4 和预测头的开销。**先测量，再估算 24 次核心训练的 GPU 小时；当前不编造运行时长。**

## 附录 A：方法的最小数学定义

### A.1 观测模型与后验

对一个窗口，设 `z ∈ R^r`，先验为：

\[
z\sim\mathcal N(0,I),\qquad
x_{tc}=\mu_c+a_{tc}^{\top}z+\epsilon_{tc},\qquad
\epsilon_{tc}\sim\mathcal N(0,v_c).
\]

`a_tc` 是可学习的时间—变量载荷，`v_c` 为正噪声方差。噪声在给定 z 后独立。令 `M_tc=1` 表示可见，则历史前缀 t 的信息形式为：

\[
J_t=I+\sum_{s\le t,c}M_{sc}\frac{a_{sc}a_{sc}^{\top}}{v_c},\qquad
b_t=\sum_{s\le t,c}M_{sc}\frac{a_{sc}(x_{sc}-\mu_c)}{v_c}.
\]

\[
\Sigma_t=J_t^{-1},\qquad m_t=J_t^{-1}b_t,\qquad
p(z\mid x_{\mathrm{obs},\le t},M)=\mathcal N(m_t,\Sigma_t).
\]

代码中用 Cholesky 解线性方程实现，不按公式直接调用通用逆矩阵。只有可见位置贡献信息；实现中必须显式掩码残差，不能把零填补位置的 `-μ_c` 加入 b。

PU-S4 的特征为 `[m_t, log diag(Σ_t)]`；STAT-S4 为 `[b_t, log diag(J_t)]`。对数输入使用仅为数值稳定设置的极小正下限，记录具体值；不额外对不同版本使用不同的数据驱动特征标准化。

### A.2 训练目标与观测似然

对 V1、V2：

\[
\mathcal L=\underbrace{\operatorname{mean}(\widehat Y-Y)^2}_{\mathcal L_{\mathrm{forecast}}}
+0.1\,\underbrace{\frac{-\log p(x_O)}{|O|}}_{\mathcal L_{\mathrm{obs}}}.
\]

上式对每个样本计算后再取 batch 平均；`O` 为整个历史窗口的可见位置。仅计算末步的联合边缘似然，不把各前缀的似然重复相加。

为避免构造大协方差，可用：

\[
-\log p(x_O)=\frac12\left[
|O|\log(2\pi)+\sum_{(t,c)\in O}\log v_c
+\log|J_L|+\sum_{(t,c)\in O}\frac{(x_{tc}-\mu_c)^2}{v_c}
-b_L^{\top}m_L\right].
\]

该损失约束载荷与方差对可见数据的解释，不能保证模型已校准。端到端预测梯度也会改变这些参数，因此须单独评价不确定性质量。

合成核对中，真实生成参数下的 oracle 读出为 `vec(Ŷ)=μ_Y+B m_L`。首轮不为这一线性读出另设可学习训练版本。

### A.3 计算量与瓶颈

主要计算包括观测信息收缩约 `O(batch·L·C·r²)`，以及所有前缀分解约 `O(batch·L·r³)`；工作矩阵约占 `O(batch·L·r²)`，此外还需要反向传播的中间量。载荷参数量为 `L·C·r`，Electricity、r=16 时仅载荷就有 493,056 个参数。

因此不能把“小型 S4”直接等同于“整网只有很少参数”，也不能忽略逐前缀求解开销。r=16 是可行性起点，实际性能由阶段 B 测量；若必须改为降采样前缀或结构化载荷，应视为方法定义变更，先更新计划和对照。
