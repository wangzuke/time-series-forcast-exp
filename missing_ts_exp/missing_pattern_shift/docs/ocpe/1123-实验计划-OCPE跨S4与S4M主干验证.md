# 实验计划：OCPE 跨 S4 与 S4M 主干的增量验证

**日期：2026-11-23。执行设备：GPU6。**  
**数据集：ETTh1、Weather、Electricity。用户所称 ETTh 按此前使用的 ETTh1 执行。**  
**实验标识：`ocpe_backbone_uniform_r50_l96_h96_1123`。**

## 1. 本轮要回答什么

核心问题是：**OCPE 能否增强 S4M 这种已经直接处理缺失数据的预测模型？** 同时比较 OCPE＋S4 与 OCPE＋S4M，判断在更强主干上是否仍有收益。

只比较两个增强模型，无法区分主干本身的优势与 OCPE 的贡献，因此保留四组：

| 组别 | 结构 | 动机和目的 |
|---|---|---|
| S4 | 历史内线性插值＋原始有效掩码 → 普通 S4 | 普通主干的基线 |
| OCPE＋S4 | 相同历史分支＋完整后验均值/对数方差分支 → 普通 S4 | 复核已实现 F3 的收益，作为横向参照 |
| S4M | 原有衰减插补、ATPM 原型检索、MDS-S4 | 缺失感知强主干基线 |
| OCPE＋S4M | 保留全部 S4M 路径，在 ATPM 输出后、首个 MDS-S4 前融合 OCPE | 检验显式条件编码的额外价值 |

本轮不增加 CTF、不新增 F1/F2 全矩阵。若完整模块没有增益，不能据此认定简化编码也无效；完整计算必要性的进一步筛选另行决定。

## 2. 结构定义：加入什么，保留什么

### 2.1 OCPE 的统一定义

两种增强模型均使用当前已实现的观测模型：窗口潜变量 rank=16，时间—变量载荷 `[96,C,16]`，变量均值与正残差方差，先验为标准高斯。逐前缀计算：

$$
J_t=I+\sum_{(s,c)\in O_t}a_{sc}a_{sc}^{\top}/v_c,\quad
b_t=\sum_{(s,c)\in O_t}a_{sc}(x_{sc}-\mu_c)/v_c,
$$

$$
u_t=[J_t^{-1}b_t;\log\operatorname{diag}(J_t^{-1})].
$$

使用完整 F3 编码，采用 Cholesky 求解。后验分支只读取真实可见观测与有效掩码，不把插值或衰减插补数值当成证据。没有动态状态转移、方差门控或未来区间输出。

### 2.2 OCPE＋S4

沿用第二轮 F3：

$$
h_t=E_{hist}([\widetilde X_t,M_t])+W_{enc}u_t.
$$

普通 S4 为两层、宽64、状态32、前馈128、dropout=0.1。保留历史分支；不把第一轮纯后验输入版混入本轮。

### 2.3 OCPE＋S4M

原 S4M 的记忆模块输出为 $c_t$，新增：

$$
\widetilde c_t=c_t+W_{ocpe}u_t.
$$

随后仍使用原始 mask embedding、首个 MDS-S4、其余 S4 层、归一化和原预测头。新增无偏置投影零初始化，使其为零时退化为对应的原 S4M。

实现用独立包装器在首层入口融合，不改写旧模型源码。新增分支不是替代 ATPM，也不改变原型检索规则；即使预测改善，也不直接称为修复检索偏移。

## 5. 训练配置与公平性边界

### 5.1 保持每个主干内部成对可比

| 参数 | S4 / OCPE＋S4 | S4M / OCPE＋S4M |
|---|---|---|
| 层数/宽度 | 2层/64 | 4层；ETTh1与Weather宽256，Electricity宽512 |
| 优化器 | 沿用AdamW及S4特殊参数组 | 原主干SGD，momentum=.9，weight_decay=1e-5 |
| 原主干学习率 | 基础1e-3 | ETTh1=.005；Weather=.001；Electricity=.01 |
| 新OCPE参数 | 纳入原AdamW配置 | 独立AdamW，lr=1e-3，weight_decay=1e-4 |
| 预测损失 | 有效目标上的标准化MSE | 相同 |
| 增强版辅助项 | 0.1×每样本按观测数归一化的历史NLL | 相同 |
| 基线辅助项 | 无 | 无 |
| 最多epoch / patience | 30 / 5 | 30 / 5 |
| 选模 | 最低source验证预测MSE | 相同 |
| microbatch / effective batch | 64 / 64 | 起始16 / 16，预检确认 |
| 梯度处理 | 沿用全模型clip=1 | 主干只检查有限性、保留原SGD；新增OCPE分支clip=1 |
| 数值精度 | FP32及S4所需complex64，关闭TF32 | 相同；不默认启用AMP |

S4M 的4层与宽度沿用此前统一框架参照，避免根据本轮测试结果挑层数。SGD取此前已采用的公开训练入口配置；新增OCPE参数采用已经验证的AdamW起点，防止替换原主干优化器后无法归因。原S4M参照与增强版的主干优化、训练批次、初始化、早停完全一致。

不同主干的宽度、优化器、batch不同，**横向结果表示这两套既定系统的表现，不是严格等容量、等优化器的主干消融**。OCPE有无的增量则在各自主干内部判断。

### 5.2 S4M记忆状态的特殊控制

S4M原型记忆不是全部注册在 `state_dict` 中，必须另外保存/恢复记忆队列、质心、计数及相关状态。训练跨epoch保留记忆，验证/测试关闭记忆写入和动量更新。

公开暖启动使用聚类，其底层随机过程未必受PyTorch种子控制。为避免同种子两组模型具有不同初始记忆，本轮按“数据集×训练家族×种子”生成一份加锁的共享暖启动产物：

- 取epoch1固定顺序的前16个训练窗口，仅使用合法可见历史；
- 暖启动时使用eval模式，避免dropout；结束后恢复原随机状态；
- 两个S4M版本加载同一初始记忆，记录其文件哈希；
- 暖启动不执行优化，不跳过任何正式训练窗口；随后完整遍历每轮相同窗口顺序。

这与旧入口“训练首batch暖启动后跳过”的做法不同，属于本轮明确的成对控制。训练、验证和测试都记录模式切换；测试固定随机种子以控制记忆超过topM时的随机子采样。此处不改变原检索算法。

## 6. 实验项、目的与执行顺序

| 阶段 | 工作 | 动机/目的 | 进入下一步的条件 |
|---|---|---|---|
| E0 协议审计 | 数据、旧F0/F3复用与掩码兼容检查 | 确保横向结果真在同一数据和掩码上 | 无身份/掩码冲突 |
| E1 接口预检 | 零投影等价、原型读取保留、隐藏占位不入后验、梯度可达、记忆保存恢复、eval不写入 | 确认模块真实接入且未破坏主干 | 预测/损失/梯度有限；恢复一致 |
| E2 GPU6效率预检 | 三数据集短步训练；测S4M显存与吞吐，并测试允许的并发 | 选择可运行batch及有益的并行安排 | 留显存余量；不因并发降低总吞吐 |
| E3 正式训练测试 | 新32次训练；每个最佳checkpoint做4项固定测试 | 获取增量与横向比较 | 失败停止派新任务，保留其他产物 |
| E4 汇总分析 | 四格MSE/MAE、逐种子方向、匹配精度、开销、掩码哈希 | 判断增益属于OCPE还是主干，并报告代价 | 保留失败和负结果，不按结果删格 |

## 7. GPU6安排与可恢复执行

GPU6为24GiB RTX3090。仅使用GPU6，不占用其他卡。先进行短预检；正式任务用独立进程、单卡可见，避免S4M内部硬编码 `.cuda()` 落到其他GPU。

初始按S4M microbatch16运行。调度以预检显存、吞吐结果决定最大并发；优先让相同数据、来源、种子的S4M成对任务相邻排队，同时穿插轻量ETTh1 S4任务。若重模型已经占满计算，允许串行，不能只看剩余显存就盲目增加任务。

不在正式训练中自动改batch。若16无法运行，在正式冻结清单前统一调整同数据集S4M两组的batch并更新计划；启动后若OOM，记录失败并停止新派发，不能静默缩batch继续。

使用tmux保持调度器存活，文件锁防止重复任务；按epoch保存last（优化器、随机数、记忆状态）与best，支持中断恢复。日志、状态、错误和CPU实时汇总分别落盘。

## 8. 报告方式与判读规则

- 主指标：标准化MSE；辅助：标准化MAE、原量纲MSE/MAE；不跨数据集平均原量纲误差。
- 各数据集列P→P、P→B_u、B_u→P、B_u→B_u四格；每训练种子先平均两个测试掩码，再统计两个训练种子的均值和样本SD。
- 主要增量：OCPE＋S4M相对S4M；参照增量：OCPE＋S4相对S4；横向比较：两个增强系统的绝对误差。
- 固定测试家族比较不同训练来源，计算错配代价；不把P→B与P→P直接称为纯错配效应。
- 同时报告匹配精度与开销。只有两个训练种子，不声明统计显著性；测试掩码不是额外独立训练。
- 若S4M更好但OCPE没有增量，则结论属于主干；若只有部分方向提升，明确适用范围；若退化，保留原始结果。

## 9. 产物与启动入口

新套件统一位于 `exp/{configs,diagnostics,results,checkpoints,logs,summary}/ocpe_backbone_uniform_r50_l96_h96_1123`（配置为同名JSON文件）。已有S4产物保持原路径，由新清单引用。

拟新增独立模块与脚本：

- `models/ocpe_s4m.py`：S4M包装、OCPE融合及记忆状态接口。
- `scripts/ocpe_backbone_common.py`：新套件身份、模型构建与复用审计。
- `scripts/run_ocpe_s4m.py`：训练、选模、记忆保存恢复与四项测试。
- `scripts/validate_ocpe_backbone.py`：公式/接口/记忆/显存预检。
- `scripts/run_ocpe_backbone_suite.py`：GPU6队列、失败状态、资源检查。
- `scripts/report_ocpe_backbone.py`：只读汇总、实际掩码一致性检查。
- `scripts/launch_ocpe_backbone_gpu6.sh`：持久化启动入口。

ETTh1的S4两个版本直接调用既有 `run_ocpe_fusion_s4.py`，传入新suite，不修改其源码。所有依赖源码在清单冻结后记录哈希；预检与正式训练需身份一致。
