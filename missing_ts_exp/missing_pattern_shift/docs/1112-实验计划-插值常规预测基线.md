# 插值常规预测基线：PatchTST、DLinear、iTransformer 实验计划

## 目的

在已完成的 r=50%、L=H=96、逐变量配平的 P/B 缺失模式 2×2 框架中，加入三个**非缺失感知**的常规多变量预测基线：PatchTST、DLinear、iTransformer。它们统一先对历史窗口做线性插值，再按各自公开实现的标准预测接口训练和测试；模型本体不接收缺失掩码。

本组实验回答的不是“这些模型是否原生处理缺失”，而是“在统一、透明的插值预处理后，常规预测器在训练/测试缺失模式变化下的表现如何”。

## 固定实验框架

| 项目 | 设置 |
| --- | --- |
| 数据集 | ETTh1、Weather、Electricity |
| 输入 / 预测长度 | 96 / 96 |
| 缺失率 | 每个变量的历史窗口精确缺失 48/96 = 50% |
| P | 分散点缺失 |
| B | 每变量两个不重叠的 24 步连续缺失块 |
| 训练—测试矩阵 | P→P、P→B、B→P、B→B |
| 训练种子 | 2024、2025 |
| 测试掩码种子 | 9101、9102 |
| 报告指标 | 原量纲 MSE、MAE；每格汇总 2 checkpoint × 2 测试掩码 = 4 个观测值 |
| DataLoader workers | 10（PatchTST、LTSF-Linear、iTransformer 三个官方训练入口的默认值） |

新增基线与已完成的 S4M/CTF/BiTGraph 共享同一 `ShiftForecastDataset`、切分、标准化、掩码生成、测试掩码和指标实现。结果写入新的隔离套件目录，绝不覆盖既有 `r50_b24_l96_h96_per_channel` 结果。

## 统一线性插值规则

对每一个 `[96, C]` 标准化历史窗口以及每个变量独立处理：

1. 保留 mask=1 的真实历史观测值。
2. mask=0 的内部缺口，按相邻真实观测时刻做一维线性插值。
3. 开头/结尾的缺口用最近的真实历史观测值延拓。
4. 本协议每变量固定保留 48 个观测，故不存在全缺失变量；实现仍会显式检测该情况，防止静默产生 NaN。
5. 插值只使用该样本的 96 步历史和该历史的观察掩码，不读取 96 步预测目标或窗口外未来数据。插值后的张量是这些模型的唯一输入；掩码不输入模型。

由于标准化是逐变量仿射变换，在标准化空间插值与先在原空间插值再标准化等价。评价始终在反标准化后的原量纲目标上进行。

## 官方代码与最小适配原则

| 模型 | 公开仓库（固定 commit） | 适配边界 |
| --- | --- | --- |
| PatchTST | `https://github.com/yuqinie98/PatchTST` (`204c21efe0b39603ad6e2ca640ef5896646ab1a9`) | 使用监督预测实现；仅由共享 runner 提供插值后的 `x` 和标准预测所需维度。 |
| DLinear | `https://github.com/cure-lab/LTSF-Linear` (`0c113668a3b88c4c4ee586b8c5ec3e539c4de5a6`) | 使用发布的 DLinear 模型；仅由共享 runner 提供插值后的 `x`。 |
| iTransformer | `https://github.com/thuml/iTransformer` (`c2426e68ca13f74aaec08045c5c724d8ad328124`) | 使用发布的长时预测模型；仅由共享 runner 提供插值后的 `x`。 |

开始全量运行前必须记录每个 clone 的 commit SHA、许可证/依赖、官方最近似的 ETTh1/Weather/Electricity 长时预测脚本，以及实际采用的命令。超参数优先遵循论文与发布脚本中的数据集/`pred_len=96` 配置；因本框架固定 `seq_len=96`、通道数和数据切分，所有不可避免的输入尺寸参数会在 protocol JSON 中记录。除输入插值、数据适配与统一记录外，不修改官方网络层、损失或训练逻辑。

## 执行与验证门槛

1. 拉取三个官方仓库到 `exp/baselines/`，固定 commit SHA。
2. 为每个模型完成一个 CPU/GPU 单 batch smoke：确认输入/输出均为 `[B, 96, C]`、参数量非零、无 NaN。
3. 对 P 与 B 各抽样 256 个窗口，记录并验证：插值后有限、真实观测保持不变、每变量原始缺失率仍精确 50%、B 的缺失块仍为两个 24 步块（插值仅在模型输入副本上发生）。
4. 用各模型官方近似配置完成一个短训练 smoke，确认 checkpoint 可恢复，且同一 checkpoint 在 P/B 测试掩码下得到可区分、可复现的预测。
5. 通过 smoke 后启动全量：3 模型 × 3 数据集 × 2 训练模式 × 2 训练种子 = 36 个训练；每个 checkpoint 在 P/B × 两个测试掩码上评估，共 144 个测试结果。
6. 汇总时只使用新套件的结果；与缺失感知模型并列呈现，但明确标记“线性插值 + 常规预测器”。

## GPU 与后台运行

- 优先分配：PatchTST→GPU 1、DLinear→GPU 2、iTransformer→GPU 5。
- 每张卡先进行相应模型的显存 smoke；若单个 worker 显存占用显著低于可用量，可同卡按 shard 并发两个 worker，否则维持一个串行队列，避免抢占其他任务或 OOM。
- worker 采用断点可重入逻辑：已有 `training_complete.json` 或测试 JSON 的任务不重复执行。
- 启动全量后建立后台状态监控，每 **3 小时** 将 worker 状态、已完成训练/测试数量、GPU 显存和异常写入隔离日志。监控只观察和记录，不会自动重启失败任务或改写结果。

## 执行修订记录（2026-11-12）

初次实现的共享 runner 固定了 `num_workers=0`。在全量任务早期核对官方训练入口后，发现 PatchTST、LTSF-Linear 与 iTransformer 均以 `num_workers=10` 为默认值。该项不改变网络、优化器、批量大小、数据、掩码或插补规则，但会改变数据加载并显著影响吞吐；为使运行路径与公开实现一致，处理如下：

- 已停止初次队列，并将其所有部分结果、checkpoint、日志、汇总和 manifest **完整归档**到 `exp/archive/1112_interpolated_regular_baselines_num_workers0/`，不删除、不与最终结论合并；
- 通过三模型 GPU smoke 后，以 `num_workers=10` 从头建立正式隔离套件 `r50_b24_l96_h96_per_channel_linear_interpolation_nw10`；
- 正式 result JSON 与 validator 均记录/检查 `data_loader_num_workers=10`。本计划及后续报告中所称“插值常规预测基线结果”均专指该 `nw10` 套件。
