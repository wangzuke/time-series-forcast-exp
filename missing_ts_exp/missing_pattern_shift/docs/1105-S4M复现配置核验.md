# S4M 训练配置核验（暂停主队列前）

核验对象：ICLR 2025 S4M 论文、作者官方仓库 `WINTERWEEL/S4M`（提交 `a718823`），以及本项目的 `exp/scripts/run_official_baseline.py`。核验日期：2026-11-05。

## 结论

当前实现保留了作者模型代码与 Weather 示例中的多数结构/记忆库参数，但**不是论文原设定的忠实复现**。它适合作为“统一的、模式漂移协议下的 S4M 实现”之前，必须先固定配置口径。为避免将不同口径的结果混入主表，已暂停 S4M 队列；已有结果只归档。

## 设备信息

论文正文、附录 D.3、补充材料表 6 以及官方 README 均**未披露 GPU/CPU 型号、数量、显存或训练时长对应的硬件**。论文只说明效率表在 Electricity、batch size 16、hidden size 512 下记录单 epoch 的训练/推理时间和最大显存。因此不能将本机两张 RTX 3090（24 GB）的耗时与论文表 6 作直接数值比较。

## 决定与执行（已确认）

用户决定以论文为标准。自 2026-11-05 起，主队列中的 S4M 固定为：Adam；batch size 16；学习率 Electricity=0.01、ETTh1=0.005、Weather=0.001；隐藏宽度 Electricity=512、ETTh1/Weather=256。论文未给出逐数据集最终层数、最大 epoch 或 patience；暂用 8 层（论文候选集且为作者 Weather 示例值）、最多 20 epoch、patience=4，并将后二者标注为本协议训练预算而非论文超参。S4M 不使用梯度裁剪或额外学习率调度。

已完成两项最小烟测：Weather(256 宽度) 与 Electricity(512 宽度) 均在本机单张 RTX 3090 24GB 上完成，峰值预留显存分别约 858 MiB 与 1,850 MiB。为阻止新队列复用旧 SGD/统一学习率检查点，旧主队列产物归档后重新运行。

### 官方实现的记忆库加速（2026-11-06）

在论文超参不变（尤其 `M=50`、`memory_size=200`、阈值和队列规则不变）的前提下，记忆库的持续状态、相似度计算和串行队列更新改为保留在 CUDA。官方实现每个 batch 将 `q` 执行 `detach().cpu()` 后逐条更新，致使 GPU 长时间等待；初始聚类仍保留官方 Bio.Cluster 的 CPU 实现，并只运行一次。GPU 版本仍按同一 CPU 随机生成器抽样，保持更新顺序。

ETTh1 的 10-batch 烟测（batch=16）完成于约 5.5 秒；保存检查点中所有 memory entry 与 centroid 均为 `cuda:0`。结果元数据的 `s4m_paper_hyperparameters.memory_update` 固定为 `cuda_serial_equivalent`，主结果将明确称为“官方实现的等价 GPU 加速版”，不会伪称未修改官方实现。

另以相同初始记忆库、相同 CPU 随机抽样和相同输入，对比 CPU/GPU 的一次完整队列更新：cluster 数均为 7，`num_dic` 完全相同，队列元素最大绝对差为 0，质心最大绝对差为 `5.96e-08`（浮点设备舍入误差）。

## 原建议（历史记录）

将结果分为两套，不能混用：

1. **论文忠实核验**：先仅做 `(ETTh1, Weather, L=96, H=96)` 的小规模预检查；batch=16，论文对应学习率，Adam；固定训练缺失掩码。它验证发布论文表述，但与官方代码的 SGD 冲突须同时报告。
2. **主问题统一协议**：保留本课题 30% P/B、L=96、H={24,96} 与动态掩码；但为公平比较，统一设定训练预算/early stopping，并在主文明确这不是原论文复现。S4M 可采用“官方代码 SGD+调度”或“论文 Adam”，二者需预先固定其一；建议以官方代码 SGD+调度为主，并做一个 Adam 小规模敏感性复核。
